# АРМАДА 6.16.0 — полный пакет согласованных рабочих доработок

Обновление поверх 6.15.0. Основной путь остаётся «Контракт → участки работ → дефекты»; НПС не является обязательной границей участка.

## Состав

1. Старые ссылки общего реестра объектов ведут к контрактам. Для ранее созданных участков без контракта есть отдельный служебный список из реестра контрактов. Участки внутри контракта остаются крупными карточками.
2. Удаление пустого ошибочного участка руководителем, с подтверждением и проверкой связанных записей. Документы, дефекты и назначения не уничтожаются каскадом; при наличии истории требуется её сохранить и использовать архивирование.
3. Во вкладке людей участка — прямое назначение работника из персонала и бригады. Логин для физического назначения не требуется. Текущие люди показываются без дублей; периоды остаются в карточках работников и бригад. Назначение не выдаёт автоматически доступ к ЛК и файлам.
4. Самостоятельное закрепление техники за бригадой, водителем/машинистом или обоими. Контракт и участок для этого не требуются. Пересечения по одной машине проверяются, периоды и история сохраняются, завершение закрепления — отдельное действие. Направление техники на участок остаётся самостоятельным процессом.
5. Документы работника: контекстный возврат из просмотра, переименование, удаление и удаление только связи с карточкой. Аналогичный возврат для техники. Переименование меняет название, а не содержимое файла. Удаление файла руководителем скрывает документ из всех карточек и удаляет сохранённые байты версий; запись об удалении и метаданные остаются для аудита. Общие исходники других собранных документов не удаляются. Файл сохранённой редакции допуска удалять нельзя, чтобы не разрушить комплект.
6. Разделение «Персонал» и «Пользователи ЛК» сохранено. Название роли объясняет, что должность сама по себе не выдаёт права. Есть явные наборы ПТО, мастера, механика, ОТ/ПБ, снабжения и исполнительной документации. Выбор набора не открывает чужие контракты и документы; дополнительные права остаются отдельными. В существующих аккаунтах разрешения автоматически не меняются.
7. Допуски: несколько комплектов одной бригады на разные контракты, участки, работы и периоды. Каждое сохранение — новая редакция с неизменяемым через интерфейс составом людей/техники и точными версиями выбранных файлов. Категории: организация/СРО, приказы, ППР, письма и приложения, ОТ, профессии, электробезопасность, согласия/прочее. Письма могут дополнять друг друга. Файл не считается согласием или пройденным инструктажем автоматически: состояние, основание, место и дата фиксируются явно. Просмотр конкретного файла и ZIP на телефон/для печати. Права руководителя/ответственного за персонал и мастера соответствующей бригады проверяются отдельно от общего реестра документов. Комплект — до 100 файлов / 200 МБ.
8. Кабинет заказчика: отдельная роль и отдельный экран. Руководитель назначает конкретные контракт и участки. ПТО готовит потребность в материалах (название, количество, единица, км, срок, состояние и пояснение). Руководитель публикует снимок хода работ, материалов и отдельно выбранных фотографий подтверждённых работ. Заказчик видит только опубликованные сведения; финансы, персонал, документы, переписка и внутренние заметки закрыты, включая прямые ссылки. Можно снять публикацию и отозвать доступ. Приёмка заказчиком показывается отдельно от подтверждённого выполнения подрядчиком. Подписание и ответы заказчика в этот режим просмотра не добавлены, так как это не было согласовано.
9. Прямое редактирование номера/км/секции/описания/координат дефекта. До появления результатов можно исправить идентификацию. После появления результатов номер и км сохраняются; описание можно уточнить с аудитом. Методы, задания, материалы и отчёты меняются через существующие формы работ. Удаление из ведомости с историей и восстановление сохранены.
10. Автоматическое создание ящиков через API Beget — подключаемая функция. Реквизиты задаёт руководитель в «Почта → API Beget», пароль хранится зашифрованным существующим почтовым ключом. По умолчанию функция выключена; существующие ящики не затрагиваются. Новые заявки обрабатывает mailworker: проверка существования → создание → подключение. Пароли существующих ящиков не сбрасываются. Неопределённые результаты не повторяются автоматически; предусмотрена отдельная проверка входа без отправки писем. Работа API зависит от доступности почтовых методов для аккаунта Beget; реальное подключение нужно проверить на сервере после ввода реквизитов.
11. ППР размером больше прежних 10 МБ можно загрузить обычным документом: лимит документа 32 МБ, прокси допускает 64 МБ запроса. Ограничения фотоотчётов и почтовых вложений сохранены отдельно.
12. Техническая подготовка публичного сайта к индексации: canonical, robots.txt и sitemap.xml. ЛК остаётся закрытым от индексации. Подтверждение владения в Яндекс Вебмастере / Google Search Console и отправка сайта выполняются владельцем; наличие в выдаче не гарантируется и не происходит мгновенно.

## Сохранение прежнего поведения

Компактная почта, автоматическое прочтение писем, счётчики, важные уведомления и корпоративная иконка из прежних пакетов сохранены. Руководство пользователя по просьбе владельца не создавалось. С NAS ничего не переносится.

Изменения схемы — добавление таблиц и одного nullable-поля; существующие объекты, документы, дефекты, почта, пароли и назначения не пересоздаются. Исторические участки, уже общие для нескольких контрактов, автоматически не разделяются и не копируются.

## Установка

1. Подключиться по SSH к серверу Beget.
2. В /opt/armada/openIA-feature-accounts-foundation выполнить bash deploy/beget/backup.sh.
3. Скачать архив, сверить SHA256 из сообщения к выпуску и распаковать поверх /opt/armada. Не заменять настоящую deploy/beget/.env и не удалять Docker volumes.
4. docker compose -f deploy/beget/compose.yml build
5. docker compose -f deploy/beget/compose.yml up -d
6. docker compose -f deploy/beget/compose.yml up -d --force-recreate proxy — применяет новый предел размера загрузки; сертификаты остаются в существующем томе.
7. Проверить версию 6.16.0, здоровье web/db и состояние mailworker. Руководителей повторно не создавать.

После установки автоматизация Beget остаётся выключенной, пока руководитель явно её не включит и не проверит реквизиты. Новому представителю заказчика нужно создать пользователя с ролью «Заказчик», затем выдать доступ к участкам и опубликовать сведения. Прежние внутренние права существующих сотрудников не изменяются автоматически.

- Запуск Docker поверх образа 6.15.0: сохранены пользователи и пароли, физические работники, назначения, контракт, участок, идентификатор дефекта, связи документа, байты приватного файла и зашифрованные реквизиты почты. Резервная копия и восстановление базы проверены.
- Caddy validate, Django check, отсутствие незаписанных миграций, проверка JavaScript и git diff --check: успешно.
- API Beget проверен подменённым транспортом: секреты в POST, защита существующих ящиков, отсутствие автоматического повтора при неопределённом результате, ограничение доступа руководителем. Живое API с реквизитами владельца не вызывалось; проверка соединения выполняется после установки из ЛК. Существующие ящики и отправка писем в тестах не затрагивались.
