# АРМАДА 6.20.0 — исправления после проверки 6.19.0

Полный пакет обновления. Закрывает восемь замечаний из [проверки опубликованной 6.19.0](CABINET_AUDIT_6_19_0_2026_10_29.md). Сохраняет структуру «контракт → участок → дефекты», персонал, технику, допуски, документы, кабинет заказчика, почту и складские данные предыдущей версии.

## Удаление и назначения

- Удаление из складской строки затрагивает только выбранный склад. Например, при остатках А — 8 и Б — 2 удаление позиции на А сохраняет две единицы на Б. На подтверждении показаны склад и количество. Для удаления со всех складов нужно отдельное явное подтверждение; движения сохраняются в истории.
- Изменение остатка после открытия подтверждения блокирует устаревшее удаление.
- Выдача муфты на работу теперь сразу видна как закрепление. Склад, распределение, подготовленные муфты и монтаж используют одно назначение. Оно снимается при возврате прежней выдачи либо изменяется явно через распределение.
- Старые явные назначения выдач переносятся миграцией. Если выдавалась групповая партия, изделия выделяются парными учётными движениями без изменения суммарного остатка. Ручные назначения сохраняются.

## Перемещение количества

«Склады» → общий перечень материалов → раскрыть строку → **«Переместить количество»**. Можно переместить, например, три муфты из десяти одним сохранением. Заводские номера и индивидуальная история сохраняются. По умолчанию перемещается свободный остаток; для резервов есть отдельный флажок. Несовместимое назначение другого участка отклоняется. Повтор одного запроса не создаёт второе перемещение.

## Excel в обе стороны

На экране наличия: **«Наличие и назначение в Excel»** → правка файла → **«Загрузить изменения Excel»** → проверка → применение.

- **Повторная поставка:** на листе «Остатки» добавлены количество, дата и источник нового поступления. Можно также добавить строку `НОВАЯ-1` того же типоразмера на тот же склад. Новая поставка получает собственную дату и источник; она не подменяется корректировкой текущей датой.
- **Корректировка:** «Новый остаток» остаётся отдельным способом исправить количество с записью корректировки в историю.
- **Перенос всей строки:** изменить склад на листе «Остатки». Перенос сохраняет количество независимо от порядка строк и наличия такого же материала на складе получателя.
- **Частичный перенос:** заполнить новый лист «Перемещения» — исходный код строки, склад получателя, количество, дата, разрешение перемещения резервов и основание.
- **Конкретное изделие:** на листе «Изделия» можно изменить склад и назначение конкретной муфты с заводским номером. Её идентичность сохраняется. Не следует одновременно менять индивидуальные назначения и итоговые количества распределения одной строки.
- **Карточка без поступления:** указать склад и начальное количество в её существующей строке. Новая карточка вместо неё не создаётся.
- **Срок работы с файлом:** ограничение восемью часами убрано. Проверка фактической версии осталась: если в ЛК изменились остатки, карточка, движения или назначения, нужен свежий файл. Предварительное подтверждение импорта действует один час.
- Старый формат обмена 6.19.0 принимается. Неизвестные склады/работы, превышение остатков и конфликтующие изменения отклоняются до записи; применение файла атомарно и защищено от повторов.

Назначение остаётся планом: закреплённая муфта продолжает числиться на складе до монтажа. Фактический монтаж и его исправления выполняются через результат ремонта. Изоляция учитывается в м², электроды — в кг с маркой и диаметром. Один материал одного типоразмера на разных складах по-прежнему показан разными строками.

## Перечень и скорость

Архивные карточки по умолчанию скрыты; для них есть фильтр «Показывать архив». История смонтированных изделий остаётся видимой. Убраны отдельные запросы на каждую муфту: проверка списка из 100 изделий требует менее 20 SQL-запросов вместо прежних 107.

## Установка и сохранность данных

Перед распаковкой выполнить `bash deploy/beget/backup.sh`. Сохранить `.env`, постоянные тома, базу, документы и ключ почты. Сборка web и обычный `docker compose up -d` применяют миграцию `projects.0022`; повторное создание пользователей не требуется. Пакет не устанавливается на VPS автоматически.

## Проверки

Изолированная копия на синтетических данных: **711 тестов PostgreSQL успешно**, **25 сценариев Chromium успешно**. После последних уточнений обмена повторно прошли 18 целевых проверок PostgreSQL склада и миграции, а также три браузерных сценария склада. `check`, `makemigrations --check --dry-run`, проверка JavaScript и `git diff --check` прошли. В Docker проверены переход с 6.19.0, сохранение старых данных, резервное копирование и восстановление базы, документов и ключа почты.

Основные проверяемые случаи: удаление одного склада при общем материале, выдача → переназначение → монтаж, сохранение старых выдач при миграции, перемещение количества с повтором запроса, поставки с фактической датой и источником, назначение заводских номеров, сохранение резервов при слиянии складских строк, атомарность импорта, права доступа, архив и количество SQL-запросов. Рабочая база и реальная почта пользователя не использовались. Контрольная сумма и исходный коммит публикуются рядом с архивом.
