# Работы и дефекты · версия 6

Выпуск добавляет модуль ремонта трубопроводов в существующий кабинет. Интерфейс 5, документы, персонал и финансовые записи сохраняются. Версия в шапке: **6.0.0-repairs**; образ web/init: **armada-test-web:repairs-v6.0.0**.

## Для мастера

На главной появляется «Мои работы». Мастер видит только назначенные ему работы в пределах объектов, к которым ему предоставлен доступ. При отзыве назначения на объект доступ к карточкам и файлам закрывается. Назначение работы не открывает финансовые сведения или чужие документы.

В карточке — место, номера дефектов, назначенный ремонт, материалы и текущий результат. Основные действия расположены вверху: «Внести результат», «Сообщить о проблеме», «Фото / пояснение». Камера вызывается отдельной кнопкой; есть обычный выбор нескольких файлов. История раскрывается по необходимости.

При внесении результата дата подставляется сегодняшняя, назначенный способ и состав показаны для проверки. Указываются фактически выполненное и весь текущий состав установленных муфт, включая изделия, внесённые при предыдущем частичном результате. Если номера пока неизвестны, это можно явно указать в пояснении. Шлифовка учитывается без муфт. Фотографии не обязательны для сохранения неполной исторической записи.

Одна ремонтная конструкция может связывать несколько дефектов. Результат и фотографии вводятся один раз. Частичный результат не закрывает связанные дефекты автоматически. Препятствия и наличие материалов учитываются раздельно. Открытое препятствие можно снять отдельным действием с сохранением истории; дата монтажа не является приёмкой заказчиком.

## Для руководителей

1. Создать участок в пределах существующего объекта: РНУ, трубопровод и название участка. Диаметр необязателен.
2. Создать работу или загрузить ведомость XLSX. Для общей конструкции номера дефектов можно перечислить через `;`.
3. Выбрать участок в перечне работ и через меню ⋯ открыть «Назначить работы мастеру». Выбрать ещё не назначенные работы и мастера; общая плановая дата необязательна. За одну операцию — до 300 работ. Прежние назначения меняются в отдельной карточке.
4. У мастера должен быть доступ к объекту. После выбора участка список допустимых мастеров подгружается автоматически. Выдать доступ к объекту может руководитель в существующей карточке объекта.
5. Проверить полученный результат и подтвердить выполнение. Эти полномочия есть только у двух руководителей. Приёмка заказчиком отмечается отдельно с датой и основанием; финансовое выполнение и деньги автоматически не создаются.

Новая запись мастера появляется в категории «На проверке» и в счётчике раздела у руководителей. После подтверждения мастер не может заменить результат. Руководитель вносит исправление отдельной записью с причиной; прежний результат, состав, подтверждение и сведения о приёмке остаются в истории. Текущая приёмка после исправления требует повторной проверки.

Одновременные изменения защищены проверкой версии. Устаревшее групповое назначение отклоняется целиком. Одну учтённую физическую муфту нельзя одновременно установить на две разные работы. Изменение связи с дефектами после начала работы через обычное редактирование задания запрещено.

## Перенос ведомости

Импорт предназначен для структуры с перечнем дефектов слева и самостоятельным перечнем муфт справа. По умолчанию выбирается последний лист; можно указать другой по имени. Файл до 10 МБ, до 300 распознанных работ на листе. PDF, XLS и другие форматы остаются доступными как обычные вложения, но не объявляются поддержанными форматами структурированного импорта.

Сначала отображается предварительный просмотр. Для каждой работы можно создать новую запись, пропустить её или выбрать предложенное совпадение по номеру дефекта в пределах выбранного участка. Кандидат по одному номеру не считается доказанным совпадением: инженер проверяет место и сведения. При появлении нового совпадения после просмотра требуется обновить список. Повторный перенос того же файла/листа в тот же участок блокируется.

При добавлении сведений к существующей работе сохраняется запись об источнике; назначенный ремонт и подтверждённый результат не перезаписываются. Новые работы создаются запланированными. Исторические даты монтажа, цвет и название месяца не превращаются автоматически в подтверждённое выполнение.

Муфты с заводскими номерами разбираются отдельно; строка справа не связывается с дефектом слева только по высоте строки. Сведения о прежнем монтаже сохраняются. Мастеру такие изделия не предлагаются как свободные. Руководитель может выбрать их при проверке соответствующего исторического ремонта, видя пометку о прежнем монтаже. Исходные наблюдения о муфтах сохраняются; повторный импорт не меняет их размеры молча.

Сохраняются объединённые строки одной конструкции, точность километра до шести знаков, текстовые номера и числовые номера с форматом ведущих нулей. Длины конструкций хранятся в метрах, отдельных муфт — в миллиметрах. Несоответствие длины и суммы состава показывается при просмотре. Формулы не исполняются, внешние книги не загружаются; используются сохранённые Excel значения с предупреждением о внешних ссылках.

Исходный файл сохраняется в закрытом хранилище с SHA-256. Ссылка доступна руководителям из предварительного просмотра и карточки перенесённой работы. Мастер не получает исходную книгу целиком: она может содержать посторонние личные или финансовые заметки. Состав данных и полноту переноса проверяет инженер; универсальное распознавание произвольных ведомостей не заявляется.

## Файлы и черновики на телефоне

До 20 вложений, до 10 МБ каждое и до 40 МБ за одну отправку. Ограничение общего объёма действует до заполнения временного диска. Изображения JPG/PNG могут показываться в истории; остальные файлы скачиваются вложением. Файлы размещаются вне публичного static и проверяются по размеру/SHA-256 при выдаче.

Открытая форма сохраняет текст, выбранные изделия и файлы в IndexedDB этого браузера. При потере связи можно продолжать заполнение. После восстановления связи пользователь нажимает «Отправить». Черновик удаляется после подтверждения сервера; потеря ответа не создаёт дубликат при повторной отправке. Если содержимое уже отправленного запроса изменилось, предлагается сохранить его отдельной записью после сверки. При конфликте с изменённой карточкой сведения не перезаписываются автоматически.

Черновики привязаны к пользователю, работе и виду действия. При явном выходе из кабинета хранилище черновиков очищается. Не следует выходить до отправки нужного черновика. Если браузер запрещает IndexedDB или места недостаточно, показывается предупреждение: страницу нельзя закрывать до отправки. Очистка данных браузера удаляет локальные черновики.

Это **не полный офлайн-режим платформы**: для первоначального открытия карточки и повторного входа нужна сеть. Автоматическая фоновая синхронизация, сохранение всего реестра без сети и распознавание фотографий ИИ не включены. GPS необязателен; получение координат браузером требует HTTPS и разрешения. В HTTP-тесте Synology можно продолжать без координат.

## Обновление существующего проекта Synology

Название проекта остаётся **armada-test**, путь исходников — `/volume1/docker/armada-test/openIA-feature-accounts-foundation`. Тома `database`, `config`, `documents` сохраняются. Повторно создавать руководителей не требуется. Не выполнять `down --volumes`, не удалять тома и не очищать весь Container Manager.

Если остановка проекта в Container Manager снова не срабатывает, в SSH-терминале NAS остановить только контейнеры платформы:

```sh
sudo docker stop --time 30 armada-test-web-1 armada-test-db-1
```

Старую папку исходников сохранить под другим именем. Новую распакованную версию разместить под прежним точным именем; `docker-compose.yml`, `server` и `deploy` должны лежать непосредственно в ней. Проверить в YAML тег `repairs-v6.0.0` у web и init.

Запуск с пересборкой:

```sh
cd /volume1/docker/armada-test/openIA-feature-accounts-foundation
sudo /var/packages/ContainerManager/target/usr/bin/docker-compose -p armada-test up -d --build
```

Новые таблицы создаются миграциями при запуске. Старые пользователи, документы и финансы не преобразуются в ремонты. После запуска проверить версию в шапке и новый раздел. `init` после успешного выполнения остаётся остановленным с кодом 0 — это нормально. Системные `synology_docviewer_*` управляются через Центр пакетов, их для обновления платформы останавливать не нужно. По окончании выйти из SSH и отключить его, если он включался только для обновления.

Полный сценарий проверки выпуска и ограничения: [REPAIRS_6_VALIDATION.md](REPAIRS_6_VALIDATION.md).
