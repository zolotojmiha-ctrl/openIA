# Продолжение разработки АРМАДА

- Перед изменениями прочитайте `docs/PROJECT_HANDOVER.md`, актуальное описание выпуска и профильные требования в `docs/requirements/`.
- Проверьте текущую ветку, коммит и незакоммиченные изменения. Не начинайте заново со старой версии из переписки. Исторические документы могут описывать прежнее состояние продукта.
- Различайте согласованное требование, проверенное поведение кода, сообщение пользователя об установленной версии и непосредственно проверенное состояние сервера. Не объявляйте причину ошибки установленной без подтверждения.
- После изменения поведения обновляйте соответствующие требования, описание реализации, проверки и оставшиеся ограничения. Новые договорённости сохраняйте в репозитории, без персональных данных и секретов.
- Не включайте в Git частное ТЗ, исходные рабочие ведомости, производственные данные, `.runtime`, ключи, пароли и резервные копии.
- Не обновляйте производственный сервер при обычной проверке кода. Для обновления нужны согласованный выпуск, проверенный пакет и сохранение существующих данных по правилам памятки.
