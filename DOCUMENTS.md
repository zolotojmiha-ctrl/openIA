# Документы · 3.0.0-documents

Модуль серверного кабинета `/cabinet/documents/`. Публичный сайт сохранён.

## Доступ и работа

- Руководители равноправны. Утверждение одной версии одним руководителем достаточно. Второе решение не перезаписывает первое.
- Сотруднику нужны общее право просмотра и назначения на **все** связанные объекты. Если документ связан с договором, нужен и доступ к этому договору. Собственные рабочие загрузки видны автоматически в этих пределах; чужие открывает руководитель отдельно. Явный запрет сильнее автоматического доступа автора.
- Сотрудник загружает и изменяет документы своего профессионального раздела с соответствующими общими правами. Загрузка требует выбора назначенного объекта. Общие документы без объекта доступны только руководителям; персональные без объекта могут быть открыты указанному сотруднику с отдельным общим правом персональных документов.
- Для скачивания нужны общее право и разрешение на конкретный документ. Автор может скачивать свои загруженные версии при наличии общего права. История чужих версий открывается отдельно. Просмотр карточки не предоставляет содержимое файла: встроенного просмотра файлов в этой версии нет.
- Файл загружается один раз, документ связывается с несколькими объектами, договорами или сотрудниками. Копий файла для каждой связи нет.
- Новая версия сразу становится текущей и получает состояние «Ожидает утверждения». Её использование возможно с предупреждением. Возврат на доработку требует комментария и запрещает скачивание сотрудниками. Руководители сохраняют доступ для проверки. Исправление загружается новой версией; прежние байты и решение сохраняются.
- Архивирование не удаляет файл и историю. Сотрудникам запрещено скачивать архивные документы. Для восстановления есть отдельное право.
- Поиск по названию и номеру документа и экспорт списка CSV учитывают доступ. Скрытые поля договоров не используются при поиске и не попадают в карточки документов.

## Хранение и ограничения теста

PDF, DOCX, XLSX, PNG, JPG/JPEG, UTF-8 TXT, максимум 10 МБ. Расширение и структура проверяются; исполняемые файлы, обычные архивы, макросы и вложенные объекты Office не принимаются. Это **не антивирус**. Установка пока предназначена для вымышленных данных в домашней сети; промышленная эксплуатация требует HTTPS, антивирусной проверки, наблюдения и настроенных внешних резервных копий.

Файлы вне публичной статики, путь задаётся `PRIVATE_DOCUMENT_ROOT`. На NAS используется новый отдельный именованный том `armada-test_documents`. Том базы `armada-test_database`, конфигурация `armada-test_config` и папки семейных фотографий не заменяются. Никакие существующие NAS-папки или Docker socket не монтируются.

Каждая версия имеет случайный путь, размер и SHA-256. Перед выдачей сервер заново проверяет байты. Повреждённый/пропавший файл даёт 503 и событие журнала. Выдача только через защищённый маршрут с проверкой прав, как вложение, без кэширования. Решения, загрузки, скачивания, архив и изменения доступа записываются в журнал.

Редактирование связей/реквизитов после создания, массовый импорт и выгрузка самих файлов архивом пока не реализованы. Экспорт CSV — только список карточек. Отсутствует автоматическая очистка оставшихся файлов после аварийного завершения процесса: удалять неизвестные файлы вручную нельзя.

## Обновление существующего проекта NAS

1. Сначала сохранить согласованную резервную копию базы, файлов и конфигурации. Не удалять именованные тома или проект.
2. Использовать архив **точного опубликованного коммита** этой версии. Проверить в `docker-compose.yml` образ `armada-test-web:documents-v3.0.0`, а не `objects-v2` и не `local`.
3. Заменить исходники в прежнем каталоге проекта. Если File Station не заменяет файлы, сохранить старый каталог под другим именем и загрузить свежий под прежним точным именем. Не менять имя проекта `armada-test`: от него зависят имена томов.
4. Создать контейнеры с пересборкой образа. Одного перезапуска старого контейнера недостаточно. База обновляется миграциями автоматически; руководителей заново создавать не надо.
5. После входа вверху кабинета должна быть надпись `3.0.0-documents`, слева «Документы» и «Ожидают утверждения». Прежний сеанс может сохраниться — это нормально. Проверить прежние учётные записи, объекты и договоры.

## Резервное копирование

Нужны **все три части**: SQL-дамп PostgreSQL (`pg_dump`), закрытые файлы из тома documents и конфигурация из config. Копирование каталога работающего PostgreSQL не заменяет дамп. Резервная копия должна храниться также вне этого NAS. Автоматическое резервирование этой версией не настроено.

Для согласованной копии остановить только web приложения; db оставить запущенной, выполнить `pg_dump -U armada_admin -d armada` внутри db-контейнера в файл резервной копии, скопировать закрытый том документов и конфигурацию, затем вернуть web. Не использовать команды удаления томов. Дампы содержат личные сведения и хеши паролей, конфигурация — секреты: хранить закрыто и шифровать внешнюю копию. Точные действия через NAS готовятся отдельно по интерфейсу установленной версии.

Серверные проверки включают восстановление метаданных после очистки тестовой базы и восстановление файлов после удаления тестового хранилища. Проверяются совпадение байтов, хеш, связи и решение руководителя. Это проверка механизма на тестовых данных; резервная копия пользовательского NAS этим не создаётся.
