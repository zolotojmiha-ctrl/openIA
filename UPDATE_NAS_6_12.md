# Установка 6.12.0 после очистки наполнения

Папка внутри архива: **openIA-feature-accounts-foundation**.
Путь на NAS: **/volume1/docker/armada-test/openIA-feature-accounts-foundation**.
Существующий проект: **armada-test**.

1. Контейнеры уже остановлены и удалены владельцем, тома armada-test_database и armada-test_documents также удалены. Том armada-test_config сохраняется. Повторять удаление не нужно.
2. Распакуйте архив. В File Station замените содержимое указанной папки исходниками новой версии. Вложенной второй папки openIA-feature-accounts-foundation внутри быть не должно.
3. В Container Manager → Проект выберите существующий armada-test → Действие → Создать. Поставляемый docker-compose.yml использует armada-test-web:feedback-v6.12.0 и содержит build. При сборке должен использоваться Dockerfile этой папки. Если используется отдельно сохранённая конфигурация YAML в DSM, замените её содержимым нового docker-compose.yml, сохранив свои NAS_IP/настройки сети и подключения config/documents/database; не оставляйте образ allocation-v6.10.1. Не создавайте второй проект с другим именем.
4. Дождитесь завершения init с кодом 0 и исправного db/web. При старте создаётся пустая база и применяются миграции. Если сборка не выполняется или появилась ошибка, используйте её текст для диагностики; не удаляйте конфигурацию или общие папки NAS.
5. В уже подключённом к NAS терминале Mac выполните:

```sh
sudo docker exec -it armada-test-web-1 python server/manage.py bootstrap_leaders
```

Последовательно введите ФИО, разные телефоны и два разных временных пароля руководителей длиной не менее 14 символов. Ввод скрытый, включая ФИО. Пароли в переписку не отправляйте. При первом входе требуется сменить временный пароль.

6. Откройте http://192.168.50.248:18080/cabinet/login/ в новой приватной вкладке браузера. В шапке версия 6.12.0-feedback. Наполнение добавляйте заново; архив его не содержит.

Функции и ограничения перечислены в FEEDBACK_6_12.md. Это HTTP-режим проверки в домашней сети; настройки публикации в Интернет не меняются.
