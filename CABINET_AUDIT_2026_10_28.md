# Проверка личного кабинета АРМАДА — 28 октября 2026

Проверена локальная копия установленной версии 6.17.0, исходный коммит `6da00ed5503ffc983a0228ed9d3815e761cdeaf6`. Исправления находятся в ветке `fix/cabinet-audit`. Новая версия и установочный архив в рамках этой проверки не публиковались, сайт на VPS не обновлялся.

## Структура входов через интерфейс

| Задача | Путь |
|---|---|
| Все дефекты и фильтры по контракту/участку | Выполнение работ → Все работы и дефекты |
| Дефекты определённого участка и скачивание Excel | Выполнение работ → контракт → участок → ↓ Скачать Excel |
| Импорт ведомости | Там же → Загрузить ведомость Excel → предварительная проверка → сохранение → исходный участок |
| Люди, техника, документы и склады участка | Участок → Люди, техника и документы участка → соответствующая вкладка |
| Документы, новые версии, комплекты, сроки | Документы → карточка файла / Ещё → Комплекты / Сроки документов |
| Проверка ежедневных работ и указаний | Выполнение работ → соответствующая кнопка руководителя |
| Массовое добавление участков | Контракты с заказчиками → Проверить участки без контракта → Массовое добавление… |
| Пользователи, права, доступ заказчика | Управление → Пользователи и права → нужная карточка или Доступ заказчика к участкам |
| Почта и подключение провайдера | Почта → ящик / подключение; настройка API — ссылка для руководителя на странице почты |
| Финансы, склады, техника, бригады, субподрядчики | Соответствующий пункт меню при наличии прав |
| Кабинет заказчика | Обычный вход пользователя с ролью «Заказчик»; он попадает в свои опубликованные контракты |

## Что проверено

- Инвентаризировано 230 именованных маршрутов, включая формы действий, скачивания, программные запросы и совместимые старые адреса.
- Автоматически пройдены видимые ссылки от главной страницы для четырёх ролей. Адреса проверяемых пользовательских страниц не подставлялись вручную в обход навигации.

В этих графах не осталось видимых переходов с ответами 403/404/500. Доступ по чужим или запрещённым прямым адресам проверялся отдельно тестами прав: отказ там является ожидаемым результатом.

- Полный основной набор: **573 теста PostgreSQL 17 — успешно**. Охватывает учётные записи, роли, документы, контракты, персонал, бригады, технику, склады, ремонты, импорт/экспорт, финансовые операции, почту, конкурентные изменения и сохранность при миграциях.
- Полный набор интерфейсных сценариев: **22 теста Chromium — успешно**. Проверяются рабочие действия в браузере, загрузки и скачивания, права, формы, подтверждения и адаптация интерфейса.
- Новый сценарий идёт только через кнопки ЛК: вход → Выполнение работ → общий список → контракт → участок → скачивание XLSX. Проверено содержимое файла: в нём нет дефектов другого контракта. Проверен переход к удалённым и обратно без потери участка и поиска.
- Для нового сценария проверены ширины 1440, 768, 390 и 320 пикселей. После финального уточнения фильтров дополнительно прошли 72 проверки PostgreSQL и три проверки браузера/выгрузки.
- Отдельно повторно проверены: старые данные ОИ/УБО, версия карточки при сохранении, пакетные операции, отрицательные остатки, защита истории, скрытые финансовые поля и ограничения заказчика.
- Часть прежних браузерных проверок отстала от уже установленной версии: ожидала прежние подписи, старую навигацию, возможность привязать один участок к новому второму контракту и предел файла 10 МБ вместо 32 МБ. Они обновлены под действующий пользовательский путь; сценарии сохранения и проверки прав оставлены, а не отключены. Проверка конфигурации также сделана переносимой между виртуальным окружением и Docker.

## Границы проверки

Это проверка кода и работающей тестовой копии с синтетическими данными, а не вход под вашей учётной записью на боевом VPS. Реальные письма, ящики Beget и финансовые записи не создавались. Почтовые соединения, ответы API и ошибки сети проверялись тестовыми серверами/имитацией; навигационный обход блокировал внешние подключения.

Боевые пароли провайдера, доставляемость реальной почты, настройки учётной записи Beget и индексация поисковиками этой проверкой не подтверждаются. Ранее показанная ошибка `decoded message length too large` с пределом 4 МБ не воспроизведена: её экран и действие пока неизвестны; такого текста/предела в коде ЛК не найдено.

В пройденных сценариях ошибок не осталось. Это не обещание отсутствия любой возможной ошибки на любых производственных данных. После согласования отчёта исправления можно собрать в отдельное обновление; сейчас установочный пакет не опубликован.
