# Проверенный кандидат 6.33.2

Исходники: f2ab77b474bd9db819cd88bf85af141fd1726d76. Это НЕПОДПИСАННЫЙ кандидат: напрямую на рабочем сервере не запускать. Результаты облачной проверки — CLOUD_VALIDATION.json и evidence/. Производственный VPS не затрагивался.

Доработаны фактические размеры/стенка/номер, связь монтажа со складским изделием и однократный расход без выдачи мастеру складских прав, выбор источника/чужого резерва, другой фактический состав вместо собственного резерва, конкретные уведомления и отдельная сверка сохранённого результата в ЛК/MAX.

Следующий шаг владельца: локально подписать этот фиксированный кандидат прежним armada-release-signing.key.pem. Команду скачивания с закреплённым коммитом и суммами предоставляет подготовившая среда. Docker, резервная копия и ключ восстановления для этого шага не нужны. Прежнее подписанное доказательство восстановления 6.33.1 проверяется, сохраняет прежнюю дату и не выдаётся за новую проверку. Во время будущей установки будет создана свежая копия текущих данных.

Внутри исходного ZIP: tools/owner_sign_6332.py и только публичные материалы tools/release_6332_baseline/. Подпись проверяет доверенный отпечаток ключа. В облако возвращается только armada-6.33.2-public-signatures.zip; ключи, база, документы и .env не возвращаются. Затем среда воспроизводит внешний подписанный архив, проверяет подписи и публикует его стандартно через downloads/nas-updates.

Внешнее приложение MAX и производственная база этим протоколом не объявляются проверенными. Ранее сохранённый монтаж исправляется владельцем после установки через карточку ремонта → «Сверить расход муфт», с предпросмотром/подтверждением. Автоматического переписывания старых отчётов нет.

Неуспешные промежуточные запуски не подменяют заключительные: тестовые данные обновлены под обязательный склад/стенку; для старых групповых остатков добавлен точный выбор склада; исправлен тестовый селектор CSRF. Первый полный установочный прогон был остановлен штатным шифрованием из-за ошибочно созданного тестового RSA-2048 вместо минимального RSA-3072; архив без шифрования удалён, старые службы возвращены. Затем на окончательном архиве с правильным синтетическим ключом успешно выполнены обновление и восстановление.
