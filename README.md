# АРМАДА | Управление

Корпоративный сайт и серверный кабинет: вход по телефону и паролю, два равноправных руководителя, сотрудники, индивидуальные права, блокировка, смена и сброс паролей, журнал действий. Добавлены рабочие объекты и договоры с индивидуальным доступом: [OBJECTS_CONTRACTS.md](OBJECTS_CONTRACTS.md).

Текущая версия **6.0.4-repairs**: работы и дефекты, мобильное внесение результатов и фотографий, черновики при обрыве связи, проверяемый импорт ведомости и групповое назначение мастеров. Документы, интерфейс и финансовый учёт прежних версий сохраняются. [REPAIRS_6.md](REPAIRS_6.md).

**Публичная рабочая установка пока не опубликована.** Учётные записи создаются владельцем установки на своём сервере. GitHub Pages обслуживает только отдельный демонстрационный прототип.

Компактная таблица и удаление дефектов: [REPAIRS_6_0_4.md](REPAIRS_6_0_4.md).

## Запуск разработки

Python 3.12, из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py migrate
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py runserver 127.0.0.1:8020
```

Маршруты: `/` — публичный сайт, `/cabinet/` — серверный кабинет, `/portal/` — отдельная демонстрация. Для тестового запуска используется SQLite. Инструкция первичного создания руководителей, требования PostgreSQL/HTTPS, настройки эксплуатации и ограничения: [SERVER.md](SERVER.md).

Не раздавать корень проекта обычным статическим HTTP-сервером: в `.runtime/` находятся приватная локальная база и служебный ключ. В Git они не включаются.

## Проверки

```sh
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py test accounts projects documents finance repairs --verbosity 1
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py check
node tests/prototype.cjs
```

Последняя команда проверяет прежний прототип через работающий Django на порту 8020. Браузерным тестам нужны Node, Playwright и Chromium; в текущей среде установлены. Серверные тесты отдельно: `test accounts.tests`.

Проверки выпуска: **176 тестов общей регрессии на PostgreSQL 17, OK**, и **41 проверка финальной редакции модуля работ на PostgreSQL 17, OK**. Проверен переход с версии 5 с сохранением входа, паролей, файлов, прав, связей, персонала и финансовых сумм. Подробности и границы: [REPAIRS_6_VALIDATION.md](REPAIRS_6_VALIDATION.md). Настоящие аккаунты и финансовые данные в проверках не используются.

## Границы этапа

Работают учётные записи, объекты, договоры, документы, персонал, финансовый учёт и модуль работ/дефектов. Черновик открытой формы сохраняется при обрыве связи, но полный офлайн-вход, офлайн-реестр и фоновая синхронизация ещё не реализованы. Распознавание фотографий ИИ, автоматические инженерные нормы и складское движение материалов не объявляются готовыми. Аварийное восстановление двух руководителей и автоматическое восстановление через почту не согласованы.

Демонстрация `/portal/` использует localStorage, переключение учебных ролей и условные данные. Это не защищённая система; реальные сведения туда не вносить.
