# АРМАДА | Управление

Корпоративный сайт и серверный кабинет: вход по телефону и паролю, два равноправных руководителя, сотрудники, индивидуальные права, блокировка, смена и сброс паролей, журнал действий. Добавлены рабочие объекты и договоры с индивидуальным доступом: [OBJECTS_CONTRACTS.md](OBJECTS_CONTRACTS.md).

Текущая версия **4.0.0-workspace**: документы, комплекты, персонал, личные настройки и финансовая аналитика с ручным учётом. [WORKSPACE_4.md](WORKSPACE_4.md).

**Публичная рабочая установка пока не опубликована.** Учётные записи создаются владельцем установки на своём сервере. GitHub Pages обслуживает только отдельный демонстрационный прототип.

## Тестирование на Synology

Пакет для локального теста: [SYNOLOGY.md](SYNOLOGY.md), файл проекта `docker-compose.yml`. Папки с личными файлами не подключаются. Этот HTTP-режим только для вымышленных данных в домашней сети.

## Запуск разработки

Python 3.12, из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py migrate
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py runserver 127.0.0.1:8020
```

Маршруты: `/` — публичный сайт, `/cabinet/` — серверный кабинет, `/portal/` — отдельная демонстрация. Для тестового запуска используется SQLite. Инструкция первичного создания руководителей, требования PostgreSQL/HTTPS, настройки эксплуатации и ограничения: [SERVER.md](SERVER.md).

Не раздавать корень проекта обычным статическим HTTP-сервером: в `.runtime/` находятся приватная локальная база и служебный ключ. В Git они не включаются.

## Проверки

```sh
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py test accounts projects documents finance --verbosity 1
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py check
node tests/prototype.cjs
```

Последняя команда проверяет прежний прототип через работающий Django на порту 8020. Браузерным тестам нужны Node, Playwright и Chromium; в текущей среде установлены. Серверные тесты отдельно: `test accounts.tests`.

Текущий полный прогон: 67 проверок учётных записей, объектов, договоров и обновления базы на PostgreSQL 17, включая браузерные сценарии. Дополнительно проверено обновление контейнерной установки с сохранением прежних аккаунтов и прав. Настоящие аккаунты в тестах не используются. Проверка production-настроек оставляет два предупреждения HSTS: для всех поддоменов и preload пока не включается до определения домена и схемы размещения.

## Границы этапа

Объекты и договоры работают в серверном кабинете. Реальные материалы пилота ещё не импортированы. Файлы документов, серверный журнал дефектов, офлайн-вход и синхронизация — следующие этапы. Разрешения на операции с документами сейчас сохраняются как настройки будущего модуля. Назначение сотрудников на объекты и доступ к разрешённым реквизитам договоров реализованы. Области доступа документов будут подключаться отдельно. Автовосстановление через общую почту и аварийная процедура двух руководителей ещё не согласованы и не реализованы.

Демонстрация `/portal/` использует localStorage, переключение учебных ролей и условные данные. Это не защищённая система; реальные сведения туда не вносить.
