# АРМАДА | Управление

Корпоративный сайт и первый серверный этап кабинета: вход по телефону и паролю, два равноправных руководителя, сотрудники, индивидуальные права, блокировка, смена и сброс паролей, журнал действий.

**Рабочий кабинет пока не опубликован. Настоящие аккаунты не созданы.** GitHub Pages обслуживает только отдельный демонстрационный прототип.

## Запуск разработки

Python 3.12, из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py migrate
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py runserver 127.0.0.1:8020
```

Маршруты: `/` — публичный сайт, `/cabinet/` — серверный кабинет, `/portal/` — отдельная демонстрация. Для тестового запуска используется SQLite. Инструкция первичного создания руководителей, требования PostgreSQL/HTTPS, настройки эксплуатации и ограничения: [SERVER.md](SERVER.md).

Не раздавать корень проекта обычным статическим HTTP-сервером: в `.runtime/` находятся приватная локальная база и служебный ключ. В Git они не включаются.

## Проверки

```sh
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py test accounts --verbosity 1
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py check
node tests/prototype.cjs
```

Последняя команда проверяет прежний прототип через работающий Django на порту 8020. Браузерным тестам нужны Node, Playwright и Chromium; в текущей среде установлены. Серверные тесты отдельно: `test accounts.tests`.

Проверены 33 теста учётных записей, включая реальный браузерный сценарий, на SQLite и временном PostgreSQL 17. Настоящие аккаунты в тестах не используются. Проверка production-настроек оставляет два предупреждения HSTS: для всех поддоменов и preload пока не включается до определения домена и схемы размещения.

## Границы этапа

Реальные объекты, договоры, файлы документов, серверный журнал дефектов, офлайн-вход и синхронизация — следующие этапы. Разрешения на операции с документами сейчас сохраняются как настройки будущего модуля. Конкретные области доступа по объектам и разделам будут назначаться отдельно. Автовосстановление через общую почту и аварийная процедура двух руководителей ещё не согласованы и не реализованы.

Демонстрация `/portal/` использует localStorage, переключение учебных ролей и условные данные. Это не защищённая система; реальные сведения туда не вносить.
