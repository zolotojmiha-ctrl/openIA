## Исправлено дополнительно

1. Уникальное имя временного контейнера восстановления перезаписывалось именем файла из архива. Вложенный путь давал недопустимое имя; возможна была коллизия с посторонним контейнером. Регрессионный тест до исправления падал, после проходит. Причина прежнего реального отказа на Mac этим не установлена.
2. Ожидание PostgreSQL переведено на TCP, чтобы не принять временный init-сервер за финальный. Первый реальный прогон до этого исправления завершился ошибкой pg_restore; исходный приватный stderr не выводился, точная причина того прогона не утверждается.
3. Ошибка упаковки и TERM оставляли открытый незавершённый архив. Оба случая воспроизведены и исправлены; SIGKILL/потеря питания по-прежнему требуют ручного осмотра.
4. Mac-запускатель сохраняет оригинальное имя копии для квитанции вместо постоянного backup.encrypted; проверено формирование команды, настоящий Mac не проверялся.
5. Разные bind-mount точки одного источника df теперь суммируются, используется минимальное доступное место. Новый тест раньше ошибочно допускал установку, после исправления отказывает до остановки служб. Одинаковые общие имена источника, например overlay, группируются консервативно; возможен избыточный отказ.
6. Диагностика сообщает фиксированные категории errno без вывода приватных имён и сообщений.

## Первоначальные ошибки и повторы

- Первый облачный прогон исходной обвязки: 57 тестов, два TimeoutExpired при лимите 60 секунд. Лимит тестового процесса увеличен до 180 секунд; производственные ожидания не сокращались. Ассерты не отключались.
- Прогон из 59 сценариев прерван после обнаружения ошибки bind-mount учёта; он не считается заключительным успешным. После исправления выполнен полный набор из 60.
- Низкоуровневые регрессии имени контейнера, незавершённых архивов и bind-mount места сначала воспроизведены падающими тестами; журналы before сохранены.
- Проверка содержимого ZIP сначала слишком широко запрещала .env.example. Уточнён только проверяющий скрипт: разрешены два штатных отслеживаемых публичных шаблона, их байты сверены с Git. Настоящие .env, ключи и данные стенда в пакет не включались.
- В Linux tool-образе сначала отсутствовал shasum для модели Mac launcher. Добавлен Perl, набор повторён успешно; код проверки хэшей не ослаблялся.
- Первоначальная конфигурация синтетического MAX была выключена, поэтому принудительно запущенный worker перезапускался. Исправлена фикстура: только синтетические настройки, пустые очереди. Это не подтверждённый дефект обновления; окончательная проверка требует нулевых перезапусков.
- Первая попытка записать кандидат в root-owned каталог стенда отказала по правам. Пакеты собирались вне стенда; приватные файлы не переносились в кандидаты.

## Не проверено / внешние условия

- Восстановление РЕАЛЬНОЙ копии владельца на доверенном Mac, Apple Silicon, причина прежнего отказа. Это обязательное условие допуска к боевой установке, остаётся открытым.
- Production/rootful VPS, реальный MAX/webhook/почта/HTTPS/Яндекс Диск, производственная подпись, публикация и установка.
- Физическое исчерпание всех отдельных томов, btrfs/zfs, абсолютная верхняя граница Docker build cache. Формулы — оценка с запасом; отказы по месту покрыты имитациями и проверкой настоящих измерительных команд.
- Docker облака rootless без cgroups: лимиты памяти не гарантированы этим стендом. Пороги Mac 1536 МиБ/512 МиБ не доказывают вместимость распакованной копии и не являются установленной причиной отказа.
- Полный прикладной/браузерный набор платформы, PostgreSQL-конкуренция и настоящее изменение схемы с отказом посередине не выполнялись в этой задаче. Миграции не менялись.
- Recovery не шифруется и автоматически не удаляется. Содержит закрытые настройки; очищать вручную по памятке.
