# Проверка интеграции MAX

Статус: локальная подготовка исходников; действующий бот не подключён. Ветка `feature/max-report-prototype`, база — опубликованные исходники 6.29.0 и отдельный офлайн-прототип. Производственный Beget, Figma, реальные письма и сообщения не затрагивались. Данные тестовые. Токен в чат не получен.

## Реализация

Постоянные привязки и черновики, одноразовая привязка с подтверждением в ЛК, отзыв, webhook с секретом/лимитами/дедупликацией, очередь обработки, пошаговая штатная форма ремонта, проверка сводки, закрытые фотографии, идемпотентная запись, уведомления о возврате со ссылкой на ремонт. Отправка отделена от решения руководителя; неопределённые ответы сети не повторяются автоматически. Устаревшие меню и уведомления проверяют действующий доступ. Запоздалый текстовый ответ отклоняется по времени события MAX.

Добавлены только миграции приложения maxbot; другие схемы и опубликованный пакет 6.29.0 не меняются. Сервис maxworker включается явно через профиль Compose. Резервирование останавливает только реально работающие писатели и возобновляет тот же набор; после ошибки тоже. Секреты поддерживают файловые настройки, MAX по умолчанию выключен. Руководство: [MAX_SETUP.md](MAX_SETUP.md).

## Выполненные проверки до фиксации исходников

- PostgreSQL 17: первоначальный профильный прогон 37 тестов OK, затем 43 и 45 тестов OK после расширения сценариев. В том числе Chromium на 320/390/768/1440, две одновременные отправки подтверждения (один отчёт), одновременный webhook (одно входящее событие), сохранение прежних пользователей/отчётов при добавлении MAX, резервирование с включённым/выключенным worker и при ошибке.
- Проверены ручной монтаж П2 с фактической длиной/номером, складская муфта с заводским номером и отсутствие повторного расхода, фактическое снятие изоляции П1, частные вложения, отзыв и смена сеанса/назначения, конфликт версии, срок черновика, обязательная сводка, чужой диалог, ограничения URL/DNS/редиректов и отсутствие токена в запросе фото, таймаут/429/Retry-After, отмена неактуальных уведомлений и меню.
- Проверка Django и `makemigrations --check --dry-run` без замечаний на промежуточной версии.
- `bash -n deploy/beget/backup.sh`, `git diff --check` — OK.
- Caddy: `caddy validate` в существующем закреплённом образе, без сети, — Valid configuration. Ограничение тела webhook 64 КиБ. Docker Compose с тестовым TLS_EMAIL разобран с профилем max; сервис maxworker присутствует. Настройки среды не сохранялись/не публиковались.
- Ранние неуспехи: неподготовленное юрлицо в изолированном конкурентном тесте, незакрытые тестовые подключения PostgreSQL, ожидание отмены сообщения при более раннем отложенном ответе, неверный импорт модели в дополнительном тесте. Исправлены фикстуры/закрытие соединений и порядок проверки доступа перед доставкой. Повторные профильные прогоны успешны.

Полный прогон и итоговая проверка зафиксированных исходников выполняются отдельно; результаты будут добавлены ниже. Не выдавать промежуточные результаты за проверку последнего коммита.

## Граница готовности

Не выполнялись реальные `/me`, регистрация подписки, загрузка с реального CDN MAX, отправка действующему боту и пилот. Источники CDN по умолчанию пусты и требуют проверки на реальных событиях. Облачная политика и отсутствие безопасно настроенного токена не позволяют подтвердить реальный API здесь. Для пилота нужен доступный HTTPS-сервер; Beget не трогали.

Новый установочный выпуск/обновление с предыдущих версий, полный архив резервирования и фактическое восстановление базы+файлов с MAX ещё должны быть проверены перед публикацией установочного пакета. Проверка миграций и сценария остановки worker не заменяет это испытание. ИИ и голос не реализованы. Сиротские файлы после аварии между записью и фиксацией метаданных автоматически не удаляются. Внешняя доставка сообщения не имеет гарантии strictly-once.
