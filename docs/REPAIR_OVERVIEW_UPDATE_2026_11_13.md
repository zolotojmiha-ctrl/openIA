# Исправление видимости дефектов для обзорного доступа

Добавлено отдельное право просмотра всех дефектов разрешённых участков. Это позволяет видеть работу другого мастера без переназначения её на наблюдающего сотрудника. Назначение на объекты и доступ к контрактам остаются обязательными. Право отправлять результаты остаётся за ответственным мастером. Подробности и границы — [требования](requirements/REPAIR_OVERVIEW_ACCESS_2026_11_13.md).

Проверки:

- 83 проверки SQLite — OK/12,188 с: новое разрешение, существующий ремонтный профиль, стартовые страницы ролей. Проверены отсутствие доступа по умолчанию, независимые границы объекта/контракта, отзыв, сохранение собственного отчёта, блокировка чужих GET/POST отчётов, прямого вызова сервиса, начала, фото, проблем, редактирования и ограничений субподрядчика.
- Те же 83 проверки PostgreSQL 17 — OK/22,391 с, включая применение accounts.0029.
- Новый Chromium-сценарий — OK/6,426 с: руководитель через существующие формы выдаёт разрешение и доступ к недостающему объекту; после входа мастера доступен чужой дефект; форма начала работ закрыта; ответственный не изменился. Ширины 320/390/768/1440 без горизонтального выхода страницы. Исправлены два ожидания самого браузерного теста (точная подпись кнопки сохранения и завершение перехода после выхода).
- 16 существующих сценариев MAX хода работ и управления прошли до завершения первого общего браузерного прогона; отдельный итоговый MAX-прогон фиксируется ниже.
- `makemigrations --check --dry-run` — новых неучтённых изменений нет. Сборка Docker с прежними офлайн-зависимостями прошла.

Порядок установки: отдельный подписанный пакет с проверкой исходных файлов, резервной копией данных и исходников, сборкой до остановки, остановкой прежних писателей, миграцией перечня разрешений, проверкой Django и запуском web/mailworker/ранее работающего MAX. Установщик не выдаёт новых прав, не снимает прежние и не меняет ответственных мастеров. На VPS код из среды разработки напрямую не устанавливался.

После установки владелец выдаёт нужному сотруднику новое индивидуальное разрешение и восстанавливает недостающий доступ к объекту. Сотрудник повторно входит в ЛК и открывает карточку «Все дефекты доступных участков». Проверку выполнять без сохранённого фильтра «мастер = я», который намеренно оставляет только собственные работы.
