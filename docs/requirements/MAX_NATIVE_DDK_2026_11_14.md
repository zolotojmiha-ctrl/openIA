# Изменение метода после ДДК целиком в MAX

Прямое поручение владельца от 14 ноября 2026: смена метода должна выполняться через бота. Все будущие новые бизнес-действия должны иметь полноценный сценарий MAX для соответствующего пользователя, включая ввод, вложения, проверку, подтверждение, отмену и исправление ошибок. Правило сохранено в AGENTS.md. Ссылка на ЛК не заменяет действие.

Сценарий: новое меню работы → «Метод после ДДК» либо /ддк → работа → новый метод → общая длина/состав/стенка для муфт → дата ДДК → основание → фотографии или документы скрепкой → проверка → явное сохранение. Шлифовка, вырезка и другой метод пропускают размеры муфты; П2 не допускает составную конструкцию. Можно исправить ответы, дополнить/удалить вложения, отменить или вернуться командой /ддк. Дата вводится ДД.ММ.ГГГГ, десятичные числа допускают запятую. Вложения необязательны; максимум 20 файлов, 10 МБ каждый, 40 МБ суммарно.

Права и изменения совпадают с ЛК: общий repairs.ddk.change и DDKForm. Мастер действует только в своей разрешённой области сдачи работ, подготовитель — по имеющемуся repairs.prepare и доступным объектам/контрактам. Новых разрешений автоматически нет. Недоступны архивные/закрытые работы и работы с уже записанным монтажом. Выбор метода не означает завершение ремонта; фактическое покрытие и монтаж вносятся отдельным отчётом после выполнения. История сохраняет прежнее задание, автора, основание, дату и доказательства. Несовместимые закрепления снимаются общим сервисом пересмотра плана; списания при этом нет.

Черновик долговечен в существующих Draft/Photo, без новой миграции. Просрочка или изменение версии задания требует явного пересмотра ответов; вложения сохраняются до обычной очистки просроченных черновиков. Подтверждение привязано к показанной сводке, кнопки вопросов — к конкретному вопросу; старые кнопки не подтверждают новые данные. Повтор вебхука/сохранения не создаёт повторную историю. Конкурирующие ЛК/MAX изменения защищены общими блокировками и версией задания. Новые действия не должны молча уничтожать активный черновик ДДК.

Файлы принимаются из официального MAX file attachment: filename и payload.url, без сохранения reuse token. HTTPS-источники — только явно разрешённые CDN, без токена бота и переходов по редиректам, с проверкой публичного DNS и ограничением чтения. ARMADA_MAX_FILE_HOSTS по умолчанию наследует ARMADA_MAX_PHOTO_HOSTS; реальный дополнительный файловый CDN можно добавить только после проверки оператором. Документы хранятся как вложения и не исполняются. Ошибка загрузки оставляет черновик и возможность повторить в боте.

Старые отправленные сообщения MAX остаются прежними: для нового действия открыть новое /меню или /ддк. Производственный пилот с реальными CDN и получением/прочтением сообщений проверяет владелец после установки. Из этой среды реальные MAX API и рабочая база не вызываются.
