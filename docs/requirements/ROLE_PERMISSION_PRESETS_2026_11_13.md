# Автоматический выбор прав по профессии

Владелец попросил проверить мастера и все роли из списка: почему у ПТО/механика галочки выбираются, а у мастера нет. Аудит исходного состояния: 12 ролей, 8 наборов; у foreman был пустой permissions, рассчитанный на персональные назначения. После добавления права отправки по разрешённым участкам мастерский набор не был обновлён. Роль сама не выбирала набор; JS применял галочки лишь по событию изменения профиля и не инициализировал базовые галочки при загрузке. Подсказка почти всем ролям показывала текст про мастера. Для accounting/ecology/subcontractor/other отдельных наборов не было.

Новый сценарий: профессия → соответствующий доступный набор → видимые галочки. Права вступают в силу при сохранении. Выбор набора также синхронизирует профессию; сервер отвергает несоответствующую пару вместо скрытого применения чужого набора. «Индивидуальная настройка» позволяет редактировать текущие галочки вручную. При смене набора его прежние базовые права снимаются, дополнительные права вне прежнего набора сохраняются. Выбор заказчика очищает и блокирует внутренние разрешения.

| Профессия | Базовый набор |
|---|---|
| Техник | Учёт аренды и загрузка документов |
| ПТО | Ежедневные ведомости, дефекты/назначения, склады/нормы, загрузка/реестры документов, указания заказчика |
| Мастер / прораб | Результаты и фото по разрешённым участкам в ЛК и MAX (`repairs.report_scope`) |
| Механик | Ведение техники и ТО, загрузка документов |
| ОТ и ПБ | Персонал/допуски, загрузка и реестры документов |
| Эколог | Загрузка и реестры документов |
| Бухгалтерия | Загрузка и реестры документов; финансовые разрешения отдельно |
| Снабжение | Склады, остатки и движение материалов |
| Исполнительная документация | Загрузка и реестры документов |
| Субподрядчик | Без общих внутренних прав; доступ по персональным поручениям |
| Заказчик | Без внутренних прав; опубликованные сведения по указанным контрактам/участкам |
| Другая должность | Индивидуальные разрешения вручную |

Для финансовой части бухгалтерии задан отдельный необязательный вопрос владельцу; до его ответа используется вариант без автоматических finance.read/finance.write. Готовые ранее согласованные наборы ПТО/механика/снабжения/ОТ и ПБ/техника/исполнительной документации сохраняют состав. Пользователь, управляющий учётками по делегированным правам, видит только наборы, все разрешения которых он сам вправе передавать. Недоступный набор не подставляется через JS и не принимается сервером.

Существующий сотрудник: показываются сохранённые права. Профиль можно распознать автоматически, только если все его базовые разрешения уже выданы; иначе остаётся «Индивидуальная настройка». Это предотвращает добавление нового права мастеру или замену индивидуальных финансовых прав бухгалтерии просто при открытии/переименовании карточки. Отдельная кнопка «Подставить набор выбранной профессии» запускает явное применение набора для существующего сотрудника. Сохранение выполняется прежним сервисом с аудитом, проверкой версии и полномочий. Установка пакета не меняет конкретных сотрудников, их сеансы, MAX-привязки или доступ к объектам/контрактам/файлам. Отдельные адресные доступы по-прежнему обязательны.

Руководители не являются дополнительными профессиями этого списка: две фиксированные руководящие учётные записи не создаются и не редактируются через обычную форму сотрудника.
