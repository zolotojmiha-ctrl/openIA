# Общая ведомость фактического выполнения для ПТО

Владелец согласовал таблицу, чтобы ПТО не открывал каждый дефект ради даты выполнения и замера покрытия. В существующем разделе «Выполнение работ» / ведомости участка добавляется «Ведомость выполнения», без нового пункта главного меню.

Одна строка на дефект в работе. Видны участок, контракт в доступном пользователю представлении, км, номер дефекта и секции, дата выполнения, ответственный мастер и автор результата при отличии, фактический метод/длина/состав конструкции, фактическая длина изоляционного покрытия, проверка и приёмка заказчиком с основанием. Карточка нужна для фото, пояснений и полной истории. Возврат из карточки сохраняет фильтры.

Показываются работы со статусами reported/confirmed. Частичные, возвращённые в работу и неустранимые дефекты не выдаются как завершённые. Берётся последний результат complete/partial/correction в порядке его внесения, а не последняя фотография/заметка/подтверждение. Это соответствует выбору результата в действующей карточке; дата выполнения не подменяется плановой датой или временем загрузки. Исправленный результат заменяет прежние значения в ведомости, история не меняется. Для старой завершённой работы без отчёта/замера — «Не указана»/«Не указан», без подстановки плановой длины; при фильтре дат запись без даты не включается. Подтверждение руководителем и приёмка заказчиком остаются отдельными фактами.

Фильтры: несколько контрактов/объектов, участок нефтепровода, ответственный мастер, период фактического выполнения включительно, проверка, поиск км/номера дефекта/секции. Неверный фильтр показывает ошибку и пустой список; Excel отказывается скачиваться, а не расширяет выборку. Если поиск нашёл дефект общей работы, остальные её дефекты остаются вместе, чтобы состав не распадался.

Общая конструкция: разные дефекты — разные строки, общие фактические значения на сайте объединены. Итоги покрытия по уникальным работам, не по количеству дефектов; неизвестные замеры явно посчитаны отдельно и исключены из суммы. Итоги по всему отфильтрованному списку, не только по текущей странице. Пагинация по 25 общих работ, конструкция не разрывается между страницами.

Excel содержит все результаты по тем же фильтрам, а не текущую страницу. В файле номера/км/идентификаторы остаются текстом; длина конструкции и покрытия — числа, по одному разу в первой строке общей работы. На остальных строках эти две ячейки пустые, есть одинаковый код общей работы для связи. Код уникальный, без обрезки UUID. Это позволяет суммировать длины без двойного учёта. Включены дата, фактический метод и состав, ответственный и автор, статус проверки, дата и основание приёмки; заголовок закреплён, доступны фильтры колонок. До 10000 работ/дефектов в файле, иначе требуется сузить фильтры, без молчаливого обрезания.

Доступ: активный руководитель, ПТО или внутренний сотрудник с repairs.prepare, только в рамках visible_jobs и видимых контрактов/объектов. Внешние заказчик/субподрядчик и мастер без подготовки не получают новый внутренний раздел. Списки вариантов фильтра также ограничены доступом. Никаких новых прав, изменений назначений, расхода, статусов или приёмки при просмотре; экспорт оставляет обычный аудит. Денежные сведения и фактический расход материалов в эту таблицу не добавляются. Старый формат Excel для импорта остаётся прежним; новая ведомость предназначена для просмотра/сверки.

Во время разработки владелец спросил о замене шлифовки муфтой после ДДК. Аудит: обычный сценарий repaired (ЛК/бот) использует метод задания и скрывает выбор; полная форма result содержит method, но основной упрощённый сценарий не даёт такого выбора. Действующий путь — изменение плана сотрудником с repairs.prepare с сохранением истории/резервов. Предложено отдельное действие мастеру для изменения метода после ДДК, с параметрами/основанием и сохранением исходного плана; это не реализовано данным пакетом и не должно называться доступной функцией.

После предложения отдельного действия по ДДК владелец ответил «Отличная идея». Зафиксирован следующий отдельный этап после установки/проверки ведомости ПТО; текущий пакет не включает изменение метода мастером.
