# Выпуск 6.31.0: сохранность обновления

Владелец 10 ноября согласовал исправления из статического обзора, включая пункты 2/3/4: фазовый откат, замену дерева приложения и резервирование. Производственные данные/VPS/Figma не использовать; исходный 6.30.0 сохранять. Отдельный коммит на задачу. Миграции и формат прикладных данных не менять, MAX автоматически не включать.

1. Запись остановлена непрерывно от начала копии до успешных миграций/проверки запуска. Самостоятельное резервирование возобновляет прежний набор служб даже после ошибки.
2. До первой попытки миграций допускается автоматический возврат прежних файлов и точных image ID. После начала миграций — остановить всех писателей и сохранить копию/дерево/инструкцию, не откатывать автоматически. Отдельный этап миграций должен предшествовать запуску писателей.
3. Заменять код целиком, сохраняя .env, блокировку, владельцев/права и имена Compose-проекта/томов. Удалённые файлы кода не переносятся. Старое дерево хранится для восстановления.
4. Опциональное локальное шифрование на открытый ключ; закрытый ключ вне VPS. Настраиваемое хранение без удаления последней подтверждённо восстановленной копии, локальные каталоги 0700. Существующий Яндекс Диск использовать повторно. Периодическое фактическое восстановление — отдельный доверенный стенд с ключом, не расшифровка в рабочую БД.
5. Подписанный SHA256SUMS и независимый доверенный публичный ключ; отсутствие проверки не выдавать за подтверждение подлинности. Приватный ключ подписи не создавать в репозитории, не включать в пакет и не выводить.
6. Полный PostgreSQL 17/Chromium-прогон на конечном исходном коммите, затем упаковка/образ/обновления/ошибки/восстановление и протокол с ограничениями.
7. Служебные корневые документы исключить из установочного архива, старые пути deploy/synology сохранить совместимыми; параметры доменов, фиксированная база PostgreSQL и ограничения контейнеров — после проверки. Уже существующие заголовки не дублировать, CSP вводить с проверкой интерфейса.

Приёмка только на синтетических данных. Внешние MAX/SMTP/Яндекс/API, публичный TLS и рабочая версия VPS по-прежнему не проверены. Наличие подписи с одноразовым тестовым ключом подтверждает только тест, не подлинность рабочего выпуска.
