# Отметки и фотографии мастера по разрешённым участкам в MAX

Уточнение владельца имеет приоритет: сотрудник уже видит нужные дефекты в ЛК, но не видит их в боте и поэтому не может отправить отметку через MAX. Требуется возможность выполнить действие по доступному дефекту, без обязательного переназначения ответственного мастера. Прежний пакет `repairs.overview` решал только чтение и этой задачи не выполнял.

Добавлено отдельное индивидуальное право `repairs.report_scope` — «Мастеру: вносить результаты и фото по всем доступным участкам». Оно действует только для активной роли foreman. По умолчанию никому не выдаётся и в ролевые наборы не добавляется. Обзорное право `repairs.overview` остаётся только для чтения. Включение нового права — отдельное явное действие руководителя в существующей форме сотрудника.

Для мастера с новым правом `visible_jobs` и общий `reportable_jobs` охватывают работы доступных объектов И контрактов независимо от assigned_to. Проверки периода назначения бригады сохраняются; архивный объект/контракт не допускает отправку. Бот показывает незавершённые работы через тот же общий фильтр, из которого получены формы ЛК, выбор участка/дефекта/фотографий и повторная проверка перед сохранением. Нельзя исправить только список, оставив сохранение закрытым, или открыть сохранение через устаревшую кнопку после отзыва доступа.

Действия: обычные начало работ, результат, сообщение о препятствии, фотографии и пояснения, фото хода работ. Метод ремонта не ограничивается П1/П2; шлифовка и остальные методы используют прежние ReportForm/нормы/фактические замеры. Подтверждение и исправление подтверждённого результата остаются за руководителем. Подготовка ведомостей, смена назначения и финансовые права не добавляются. Ответственный мастер не изменяется автоматически, новые отчёты и фото записываются на фактического автора. Прежняя история сохраняется.

Для всех остальных пользователей сохраняются прежние правила. ПТО/субподрядчик/заказчик/другая должность не получают это расширение даже при ошибочно записанном одноимённом разрешении. Прежние ограничения субподрядных поручений остаются обязательными.

После сохранения прав существующая форма завершает прежние сеансы пользователя. MAX-привязка связана с session_version: сотрудник заново входит в ЛК и подтверждает подключение MAX через профиль. Эту проверку нельзя молча обходить. После перепривязки «Мои работы» / `/работы` и «Фото хода работ» используют новый доступ. На главной и в реестре ЛК пояснения различают обзор и разрешённую отправку по участкам.

Миграция accounts.0030 меняет только перечень значений индивидуального разрешения. Ни конкретные права сотрудников, ни данные о назначении мастеров установщик не меняет. Отсутствующий доступ к объекту/контракту по-прежнему настраивается отдельно. Наличие нужного участка в рабочей базе подтверждено скриншотом владельца, но выдачу нового права и фактическую работу после установки должен подтвердить владелец.
