# Требования пользователя: склад и распределение муфт — 28.10.2026

Статус: реализовано в подготовленном обновлении 6.18.0 по последующему поручению пользователя. Подробности и границы: RELEASE_6_18.md. Основание: сообщения пользователя и файл «!Таблица по муфтам ОМСК, НСК 24-26.xlsx», лист «НСК РНУ 08.2026», Z3:AI64 и A3:Y63. Сам файл с производственными данными в репозиторий не добавлять.

## Основной пользовательский сценарий

Добавить физические муфты на определённый склад → видеть их в остатках → распределить конкретные изделия между дефектами ведомости участка → видеть контракт, участок, нефтепровод, км и номера связанных дефектов в складе → зарегистрировать монтаж → сохранить историю и исключить изделие из физического остатка. Резервирование не равно монтажу и не списывает остаток; зарезервированное изделие нельзя повторно обещать другой работе.

По Excel подтверждены три состояния:
- Зелёная строка и км в Z: смонтировано. Пример: строка 11, П2 1000×8, №4575, км577.192, факт11.08.2026.
- Без зелёного, км в Z заполнен: лежит на складе, зарезервировано под конкретную работу. Пример: строка37, П2 1500×8, км153.569, заводской № ещё отсутствует.
- Без зелёного, Z пуст/прочерк: свободное изделие. Примеры: строки38–41, П2 1500×8.

Цвет в ЛК дублировать явной подписью статуса. Связь хранить с работой/дефектами, а не только числом километра: одинаковые км бывают на разных нефтепроводах. Несколько изделий могут относиться к одной конструкции; одна конструкция может закрывать несколько дефектов. В таблице примеры нескольких муфт на км549.916/549.928. Состав конструкции из левой таблицы учитывать при расчёте потребности, не считать автоматически «один дефект = одна муфта».

## Колонки и структура

Общий понятный алфавитный список с фильтрами склада, типа материала, статуса, контракта/участка и назначения. Колонки: порядковый номер; наименование; категория (муфта, композит, герметик, изоляция); тип муфты П1/П2/…; диаметр; длина мм; стенка мм; заводской №; склад получения; дата получения; текущее место хранения; количество/единица; назначение (нефтепровод, км, дефекты); статус. Заводской № необязателен при приёмке, доступен для заполнения позже. Не выводить технический UUID вместо рабочих характеристик.

Муфты учитывать поштучно даже без заводского номера, с внутренним идентификатором. Композит и герметик — количество шт. Изоляция — квадратные метры (м²): пользователь проверил единицу получения и уточнил её 28.10.2026. Это заменяет прежнее указание о тоннах. В исходном Excel изоляция обозначена «м», а «Купер» тоннами: не выполнять автоматическую конвертацию старых количеств без подтверждения исходных единиц.

Excel также содержит факт монтажа, дату доставки, передачу паспорта в ПТО, массу. Склад получения/источник отличается от текущего места хранения; перемещения сохранять. В AG есть будущие даты29.10,02.11,03.11.2026: не включать ожидаемую поставку в фактически полученный запас лишь по наличию строки/даты.

## Достаточность материалов

Показывать потребность по незавершённым конструкциям, получено/на складе, зарезервировано, свободно, смонтировано и нехватку по совместимым характеристикам (тип, диаметр, длина, стенка). Не подменять совместимость общим количеством. Не учитывать смонтированные изделия как запас; не считать одну и ту же муфту в обеспечении нескольких работ. Правила допустимых замен размеров требуют отдельного согласования, самовольных замен не делать.

## Почему текущая позиция не попала в остатки

На скриншоте «Материалы и муфты» создана запись справочника. По коду stock_views.ItemForm/save_item создание позиции не формирует поступление и не выбирает склад. Физический остаток появляется через stock.move(receipt, destination, quantity, date). Поэтому сохранение карточки само по себе не означает поступления на «Володя Барабинск». Боевой БД нет в доступе, конкретную запись/её движения на VPS не проверяли.

Требуется простой вход «Добавить материал на этот склад»: склад подставлен, создание карточки и поступление одним сохранением; после него возврат к остаткам с видимой новой строкой. Справочник явно отделить подписью от реального наличия; не требовать знания внутренней бухгалтерской схемы. Не создавать автоматически остаток1 из старой записи без подтверждения склада, количества и даты.

## Удаление

Пользователь требует действие «Удалить» в перечне складских позиций, отдельно от архива. Добавить меню действий, подтверждение с понятным результатом. Для ошибочно заведённых записей без истории — удаление; для проведённого поступления — отмена ошибочной операции с корректировкой остатка и сохранением истории. Не скрывать требование удаления за единственным «В архив» и не уничтожать историю монтажа/движений каскадно.

## Будущая проверка

Приёмка муфты без заводского № и дописывание позже; сразу видимый остаток на выбранном складе; резервирование и снятие резерва; запрет двойного резерва; несколько муфт/дефектов на конструкции; монтаж и списание ровно один раз; движение между складами; достаточность по размерам; отсутствие смонтированных в доступном запасе; ожидаемые поставки отдельно; удаление ошибочной позиции; корректная отмена поступления; права и конкурентное редактирование.
