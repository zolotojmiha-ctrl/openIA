# П1: готовые нормы ПТО и отмена ошибочной складской операции

2 ноября 2026 года владелец подтвердил ответ ПТО: только П1, только цветные столбцы таблицы, пока труба 720 / муфта 760 мм, все округления уже выполнены. После отдельной просьбы лишь обсудить вопрос владелец прямо разрешил программирование. Реализация — ветка feature/p1-coating-and-stock-undo поверх опубликованной 6.25.1.

## Принятые нормы

- В p1_coating_table.json записаны 15 готовых строк для длин 1–8 м с шагом 0,5 м: длина конструкции, длина/площадь очистки, общая площадь изоляции, расход грунта, Ксизола и обёртки. Это нормализованные утверждённые данные приложения; исходный снимок рабочей таблицы в Git не добавляется.
- Для килограммов берутся именно готовые значения цветных столбцов. Площадь не умножается заново на удельные коэффициенты; серые/белые расчётные столбцы не используются. Дополнительного округления и запаса нет.
- П1 из нескольких секций считается одной конструкцией по общей длине: 2+2 м используют строку 4 м, а не две строки 2 м. При фактическом монтаже более длинного изделия используется его реальная суммарная длина; исходное требование дефекта сохраняется.
- Для других диаметров, отсутствующих длин и длин свыше 8 м нормы покрытия не выдумываются. Известная потребность герметика/композита по РД остаётся видимой; отсутствие покрытия отражается причиной для уточнения. П2 продолжает рассчитываться по прежним профилям, таблица П1 к нему не применяется.
- В настройках норм ПТО видит таблицу П1; на телефоне — карточки с подписями всех величин. В карточке ремонта видны соответствующие размеры очистки/изоляции. Для частичного монтажа это план всей конструкции, а после полного результата — норма по фактическому составу.

## Потребность и фактическое списание

Потребность и XLSX включают табличные кг вместе с существующими комплектами герметика/композита. Остаток подбирается по совместимым складским категориям и единицам на обслуживающих складах: покрытия — кг, комплекты — kit либо прежние pcs. Старые м² автоматически в кг не переводятся. Фактические движения сохраняют конкретную карточку, склад и количество.

Новая полностью завершённая П1 автоматически проводит пять материалов — герметик, композит, грунт, Ксизол и обёртку — одним проверенным набором. Частичный результат сам по себе расход не проводит. Если позиции/количества не хватает, результат и выбранная муфта сохраняются, материалам назначается ожидающее списание; половина набора не списывается. После уточнения остатков ПТО повторяет списание из карточки ремонта.

Повтор отчёта и исправление пояснения не дублируют расход. Изменение фактической конструкции после проведения требует сверки прежних материалов. Уже выполненные П1 без прежнего автоматического учёта не списываются задним числом при коррекции.

Если по П1 уже есть неотменённое ручное списание нормируемого материала, автоматическое не дублирует его: появляется причина сверки. Ошибочную ручную операцию можно отменить в складской истории, затем нажать «Проверить списание после сверки». При действительной ручной операции она остаётся фактом в журнале. Миграция projects.0029_material_review_reason добавляет только причину проверки; старые суммы/движения/снимки не переписывает.

## Отмена удаления позиции

Причина исходного поведения установлена по коду: удаление карточки проводилось как automatic loss с основанием «Удаление ошибочной позиции». Общая защита автоматических ремонтных списаний скрывала кнопку отмены и запрещала такую отмену, а история неверно подписывала удаление как результат ремонта.

Теперь этот конкретный серверный вид удаления распознаётся отдельно, включая прежние записи. История показывает «Удаление позиции» и кнопку «Восстановить удалённое». Подтверждение явно указывает материал, количество и склад. Обратная запись возвращает количество на исходный склад, при необходимости снимает deleted_at/архив с карточки. История и исходная операция остаются; отменённая строка помечается и больше не предлагает повторную отмену.

Одна отмена относится к выбранному движению и его складу, не ко всем похожим позициям и не ко всему пакету удалений. Права stock.manage обязательны. Повтор запроса и одновременная отмена двумя сотрудниками не удваивают остаток. Архивный склад, неподходящее текущее состояние или установленная муфта по-прежнему защищены; ошибка полностью откатывает и изменение карточки, и складское движение. Автоматический физический расход ремонта не превращается в произвольную ручную отмену из складского журнала.
