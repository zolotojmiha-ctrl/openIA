# Завершение выпуска 6.33.1 через терминал владельца

Подпись выполняется существующим ключом, который найден у владельца и проверен по прежнему DER SHA-256. Копия ключа старой облачной среды недоступна. GitHub Actions/Secrets для этого порядка не требуются: экспериментальный workflow удалён из основной ветки. Закрытый ключ не запрашивается в чате и не передаётся разработчику.

## Один локальный шаг

`tools/owner_finish_6331.py` запускается на доверенном Mac, где уже находятся реальные копия и ключ восстановления. Это проверка реальной копии владельцем, а не перенос испытаний платформы с облачного стенда. Docker Desktop должен быть запущен.

Скрипт последовательно:

1. Проверяет, что используется локальный Docker Desktop, а не удалённый endpoint.
2. Через окна выбора получает пути к трём существующим файлам: реальная `.encrypted` копия из ЛК, её закрытый ключ восстановления, `armada-release-signing.key.pem`.
3. Скачивает только публичные файлы кандидата по неизменяемому коммиту GitHub, проверяет закреплённые суммы. Ключи и копия не попадают в контекст сборки.
4. Собирает проверенный recovery-образ с офлайн-колёсами и обязательными хэшами. Копия и ключ восстановления передаются read-only. Во временной изолированной БД без сети выполняется настоящее восстановление, сверка строк и файлов. Квитанция текущего запуска проверяется по SHA-256 выбранной копии.
5. Только после успеха использует прежний ключ подписи, ещё раз сверяет независимый отпечаток, подписывает внутреннюю ведомость и внешний ZIP. Ничего не устанавливает на VPS и ничего не загружает в сеть.
6. Создаёт `armada-6.33.1-public-signatures.zip` — небольшой публичный ответ для передачи Codex. Он содержит только подписанный JSON, ведомость, подписи и открытые ключи подписи/резервирования. Публичный ключ резервирования выводится из проверенного ключа восстановления и используется только для предустановочной копии; закрытый ключ не передаётся. Закрытых ключей, резервной копии, документов и локальной квитанции там нет.

После получения публичного ответа Codex воспроизводит побайтно тот же внешний ZIP из уже имеющихся публичных файлов, независимо проверяет обе подписи и публикует обычным коммитом в `downloads/nas-updates`. Только после повторного скачивания и проверки даётся команда установки владельцу.

## Ограничения

Профиль восстановления: минимум 1536 МиБ Docker VM, `.encrypted` до 512 МиБ, контейнер проверки 512 МиБ памяти и tmpfs /tmp 2 ГиБ, временный PostgreSQL 512 МиБ/768 МиБ tmpfs. Это ограниченный профиль, не гарантия вместимости распакованной копии. При недостатке ресурсов/ошибке подтверждение не выдаётся и подписание не выполняется. Проверку TLS/подписи/сумм не отключать. Причина прежнего реального отказа не объявляется установленной.

Не отправлять папку `local-receipt`, копию или закрытые ключи. При неудаче передавать только итоговый этап и код, не приватный вывод.

## Проверки

Пять unit-сценариев: детерминированная реконструкция внешнего ZIP и проверка подписи, публичный ответ без закрытых данных, запрет размещения private inputs в build context, отказ неправильной квитанции, запрет вызова signing после неудачного восстановления. Реальная функция восстановления проверяется отдельно в облаке на синтетической зашифрованной PostgreSQL-копии. Реальный Mac/копия владельца ещё не проверены до запуска владельцем.
