# MAX: отправка отметки по доступному дефекту

Пакет добавляет явное право мастеру отправлять результаты и фотографии по всем разрешённым ему участкам, сохраняя ответственных и историю. Подробные границы: [требования](requirements/MAX_SCOPED_REPAIR_REPORTING_2026_11_13.md). Прежний обзорный доступ остаётся только чтением; по умолчанию права других сотрудников не расширяются.

Изменяется общий фильтр отправки, а не только список бота. Поэтому согласованы выбор участка/работы в MAX, фото хода работ, реестр/формы ЛК, проверка исходящих уведомлений и повторная проверка при сохранении. Для уполномоченного мастера доступны незавершённые работы разрешённых объектов/контрактов, с сохранением периода бригады. Существующие проверки состояния, версии, физических муфт, фактического покрытия и двойной отправки продолжают работать.

Проверки:

- 146 проверок SQLite — OK/16,474 с: профиль MAX, фото хода работ, прежний обзорный доступ и ремонтный профиль.
- 147 проверок PostgreSQL 17 — OK/34,614 с; дополнительно проверен период бригады и применена accounts.0030.
- Заключительный профиль SQLite/Chromium — 21 тест OK/10,681 с: новый доступ, главные страницы, прежняя браузерная выдача обзорного доступа; отдельная проверка повторной MAX-привязки после изменения session_version.
- Новые сценарии используют настоящие обработчики Inbox/Outbox/Draft, ReportForm и report_work с синтетическими событиями и подменённой загрузкой фото. Проверен путь: разделы → работа на км → отчёт шлифовки с фактической длиной покрытия/фото → подтверждение отправки → сохранение одного отчёта с фактическим автором и прежним ответственным. Отдельно фото хода работ. Доступ проверяется перед выдачей и перед сохранением; отзыв блокирует старый ответ/отправку и сохраняет фото черновика. Обзорное право без нового разрешения не открывает отправку, другие роли не получают расширения.
- `makemigrations --check --dry-run` — нет пропущенных миграций. Docker-сборка с прежними офлайн-зависимостями успешна.

Настоящий API MAX не вызывался, сообщений сотрудникам/заказчикам из среды разработки не отправляли, рабочая база не менялась. После установки руководитель отмечает у выбранного мастера новое разрешение; мастер повторно входит в ЛК, подтверждает подключение MAX и открывает «Мои работы» или «Фото хода работ». Сохранённый фильтр по своему имени в ЛК по-прежнему ограничивает список собственными назначениями.

Отдельный подписанный пакет использует проверку исходных файлов, резервную копию данных/исходников, сборку до остановки, остановку писателей перед миграцией, проверку Django и запуск прежних служб. Изменение accounts.0030 относится только к перечню индивидуального разрешения. Назначения, права и привязки автоматически не переписываются. Исправление меню телефона сохраняется в том состоянии, в котором было установлено владельцем; данный пакет его файлы не заменяет.
