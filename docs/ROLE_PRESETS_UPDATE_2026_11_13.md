# Профессии и автоматические галочки прав

Исправлены синхронизация профессии/набора, инициализация галочек, содержимое мастерского набора и пояснения для всех 12 ролей. Добавлены отсутствовавшие профили бухгалтера, эколога, субподрядчика и другой должности. Полный состав и границы: [требования](requirements/ROLE_PERMISSION_PRESETS_2026_11_13.md).

Мастерский набор теперь содержит ранее реализованное `repairs.report_scope`; просмотр не подменяет право отправки. Установка не выдаёт его массово действующим мастерам. При открытии уже созданной учётки сохранённые права остаются источником истины; для явного применения выбранной профессии есть отдельная кнопка. Индивидуальные дополнительные разрешения сохраняются вне заменяемого базового набора. При custom-режиме текущие галочки разблокируются для редактирования. Заказчик не получает внутренних прав, а субподрядчик работает в рамках персональных поручений.

Проверки:

- Аудит: каждая из 12 ролей имеет набор, все ключи разрешений существуют, стандартные наборы не включают управление пользователями/адресным доступом. Финансовые права не добавляются другим профессиям.
- 121 тест SQLite — OK/14,587 с: формы/сохранение пользователей, роли, техника/ТО, ПТО/склад/заказчик, мастерские отчёты MAX и прежнее обзорное право. Дополнительный заключительный профиль форм: 10 тестов OK/0,449 с, включая сохранность индивидуального финансового права бухгалтера.
- Два Chromium-сценария — OK/10,271 с: перебор всех 12 профессий, совпадение профиля и галочек, синхронизация в обратную сторону, сохранение ручного дополнительного права, custom-режим, изоляция заказчика, фактическое создание мастера с правильными записями AccessGrant. Для старого мастера без разрешений проверены открытие без нового права и явное применение набора без сохранения. Прежний обзорный сценарий остаётся только чтением.
- Ширины 320/390/768/1440 без выхода формы за экран; снимок телефона сделан до создания временного пароля. Ошибок JavaScript нет, `node --check` проходит. `makemigrations --check --dry-run` — изменений схемы нет.

Реальные сотрудники/финансовые записи не читались и не изменялись из среды. Вопрос о финансовом наборе бухгалтерии необязательный; при отсутствии ответа применяется документный набор с отдельной выдачей финансовых прав. Это не считается согласием владельца на выдачу финансового учёта.

Пакет содержит форму, описание наборов, клиентский скрипт и шаблон сотрудника. Новая версия URL скрипта исключает использование прежней клиентской логики после обновления страницы. Миграций/новых зависимостей нет; нужны ранее установленные права мастерского MAX-отчёта accounts.0030. Существующие права и MAX-привязки не меняются установщиком. После установки обновить форму пользователя в браузере; изменения выбранного сотрудника применяются только при сохранении.
