# Выполненные дефекты 2026 в действующем контракте

Владелец поручил добавить все подтверждённые выполненные дефекты 2026 года по всем участкам МН Омск — Иркутск в действующий договор ТЗС-1731-2025. Это отдельный перенос от архива 2024–2025: действующий договор не закрывается, новые записи имеют обычное состояние confirmed и показываются в «Устранённых» и ведомости ПТО, не в начальном списке работ.

## Источник и границы

План JSON готовится из ранее предоставленной книги с учётом пояснений владельца. Зелёный километр подтверждает выполнение, но дата в явно плановой колонке не превращается в дату завершения. Неизвестные даты остаются NULL; дата монтажа частей сохраняется отдельно. Исполнитель и фактическое покрытие не выдумываются. Заводские номера/размеры являются снимками источника, не складскими приходами или списаниями. Подтверждённые недоделанные строки исключаются. Уточнённые координаты одного дефекта на позднем листе не создают второго дефекта. Несколько дефектов на одном километре не объединяются автоматически в общую конструкцию.

Сам JSON, исходная книга, выгрузка ЛК и результаты частной сверки остаются вне Git и публичных пакетов. В публичном коде только универсальная проверка и синтетические тесты. План фиксирует UUID договора, номер ТЗС-1731-2025 и контрольную сумму строк. Статус договора должен быть active, организация и связанные существующие участки проверяются. Новые участки/разделы не создаются и существующие метаданные не меняются.

## ЛК и MAX

В карточке выполнения контракта руководителю доступно «Добавить выполненные дефекты 2026». В MAX: «Устранённые» → «Добавить выполненные 2026» или /импорт_2026. Сценарий полностью нативный: выбор действующего договора, вложение частного JSON, сводка добавлений/пропусков/совпадений, страницы записей, источники, подтверждение и отмена. Переход в ЛК для этого не требуется. Загруженный план не изменяет базу без подтверждения. Активный перенос не перехватывает чужой незавершённый полевой отчёт и не теряется при /меню.

Обе поверхности вызывают repairs.completed_import. Применение доступно только активному руководителю с актуальной сессией; чужой предпросмотр недоступен. Подтверждение действует 24 часа, ЛК связывает его с актором/сессией/сводкой, MAX — с текущим переносом привязки. Очередь MAX повторно проверяет разрешение, активный целевой договор и отмену сводки.

## Совпадения и запись

- Отсутствующий дефект: новая обычная Job, Defect и JobDefect, state=confirmed. У известной даты создаётся обычный Report с пометкой импорта; автор записи — оператор, не заявленный исполнитель. Без даты используется прежнее представление результата с NULL, без фиктивного Report на день импорта.
- Точное уже подтверждённое совпадение в этом договоре: пропуск; старые отчёты, метод, координаты, назначения, даты и источник не перезаписываются.
- Текущая работа, удалённая запись, неоднозначность, изменившиеся координаты/секция: строка удерживается для проверки, не добавляется и не перезаписывается. Остальные независимые строки переносятся.

Перед применением повторно проверяются привязки участков и отпечатки совпадений. Изменение базы требует нового предпросмотра. Актор → договор → предпросмотр блокируются в едином порядке; две конкурирующие загрузки не добавляют один набор дважды. Сбой посередине откатывает весь перенос. Повтор того же выполненного пакета — без новых записей. Договор остаётся active; приёмка заказчиком не выставляется. Источник completed_register_import отделён от historical_import архива 2024–2025.

Новых моделей, миграций, прав, движений склада, назначений, индивидуальных ремонтных уведомлений и новых верхних пунктов меню нет. Существующий сервис архива не ослаблен.
