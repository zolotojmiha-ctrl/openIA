# Протокол кандидата 6.33.2

База приложения: 6.33.1, `a31400fad1fa63476f978a042cf046a83c600daa`. Разработка: `feature/coupling-stock-notices`. Дата: 15 ноября 2026. Только синтетические данные; производственные номера дефектов/муфт и результаты частной диагностики не включены в исходники/тестовые фикстуры.

## Среда

Облачный Linux, Python 3.12.14, Django 5.2.18 и остальные зависимости из локального `deploy/synology/wheels/requirements.lock` с проверкой хэшей, без PyPI. PostgreSQL 17 в отдельном контейнере с tmpfs и портом только 127.0.0.1. Браузерные проверки: Chromium и Playwright в облаке. Закрытых ключей владельца, производственной БД, сообщений сотрудникам и подключения к VPS нет.

## Проверенные свойства

- Ненумерованное свободное изделие получает фактический номер и списывается до приёмки результата; неправильная стенка остаётся свободной.
- Нет совместимого остатка/стенки/корректного номера — отчёт не создаёт фиктивного монтажа без склада, транзакция откатывает изменения.
- Свободное наличие не забирает чужой резерв. Выбранный чужой резерв перераспределяется с версией прежней работы и неизменяемым аудитом. Несовместимый/подделанный выбор отвергается.
- В составном ремонте ошибка последнего изделия откатывает весь набор. Ранее созданная несвязанная запись физического изделия переиспользуется.
- ЛК/MAX используют один сервис. В MAX обязательная стенка, листание длинного перечня источников, подтверждение фактов и конкретный складской расход. Уведомления перепроверяют права и реальность проводки.
- Сверка старого результата: предпросмотр не изменяет склад; подтверждение сохраняет прежний отчёт и состояние проверки, проводит недостающий расход; повтор, устаревший предпросмотр и отзыв роли обработаны.
- PostgreSQL-конкуренция: два запроса одного отчёта — один расход; две работы на последнее изделие — один успешный результат; два подтверждения сверки — одна проводка. Также прежние конкурентные сценарии ДДК ЛК/MAX.
- Браузер: обязательные поля/стенка/номер, ручной и закреплённый монтаж, возврат к списку, уведомления и приёмка; четыре отказа IndexedDB не блокируют передачу; мобильные формы и предпросмотр сверки.
- Подпись публичных файлов временным синтетическим ключом, независимая проверка и точное воспроизведение внешнего ZIP, отказ при изменённом кандидате/прежнем доказательстве/ключе; закрытые ключи не входят в ответ.

Заключительный прогон приложения: **235 тестов, OK, 132,628 с, пропусков нет**. Включены PostgreSQL-конкуренция и шесть браузерных сценариев, включая мобильную сверку. Также прошли **60 тестов установщика (610,643 с)**, **5 криптографических проверок подписи/воспроизведения ZIP (0,890 с)** и **2 теста упаковки (0,007 с)**. `makemigrations --check --dry-run`: No changes detected. Python/JavaScript syntax и `git diff --check`: OK.

Дополнительно проверены фактический состав вместо собственного резерва (ЛК/MAX), освобождение неиспользованного собственного резерва только при полном завершении, точный склад для старой групповой позиции на разных складах, две единицы одного группового остатка при сверке. Приоритет по фактическому известному номеру выше свободного ненумерованного наличия: не подменяется реально установленное изделие.

На отдельном контейнерном стенде исходной 6.33.1 воспроизведён разрыв: реальное свободное ненумерованное изделие есть, старый ручной монтаж создаёт результат без складского движения. Проверка обновления этого стенда **из окончательного архива** и восстановления созданной установщиком копии выполняется после фиксации исходников; её итоговый протокол поставляется рядом с кандидатом вне неизменяемого ZIP. Это не подразумевает проверку производственных данных.

Первые SQLite/контейнерные запуски выявили тестовые сценарии без поступления/обязательной стенки и отсутствие Node в прежнем образе инструментов. На PostgreSQL выявлены необходимость нормализовать 10.00 для целочисленной стенки и обновить браузерные фикстуры под обязательный ввод. Неуспешные прогоны не объявляются успешными. В мобильной проверке исправлен неоднозначный тестовый селектор CSRF (в шапке есть отдельная форма выхода).

Команды воспроизведения прикладываются к артефактам кандидата. Неизмеренные свойства: реальный MAX, текущее содержимое VPS, все возможные нестандартные старые складские данные. Переназначение неизвестного физического изделия за пределами текущего объекта/контракта не производится.
