# Обновление ДДК и совместного контроля аренды

Состав и границы: [требования](requirements/RENTAL_DDK_COLLABORATION_2026_11_13.md). Дополнены существующие ремонты/техника и MAX, новые пункты главного меню внутренним сотрудникам не добавлялись. Прогноз дат остаётся отдельной согласуемой постановкой, архив почты на Диске не реализуется.

Проверки:

- 22 новых сценария SQLite: ДДК/повтор/версия/файлы/права, изоляция арендодателя, финансовый флажок, разногласие без изменения табеля, часы/корректировка/21:00/позднее заполнение/отзыв MAX, агрегация/DN/переименование/тихая базовая точка — OK/2,369 с.
- Широкий профиль: accounts, repairs, maxbot, аренда/механик, денежные формы и Chromium — 445 тестов за 220,604 с: 8 PostgreSQL-пропусков, один сбой прежнего браузерного сценария фото при ожидании ленты. Этот сценарий повторён отдельно с временным хранилищем и прошёл; первоначальный сбой не объявляется доказанной прикладной регрессией или проверкой VPS.
- 53 PostgreSQL-теста новых функций, ведомости ПТО, напоминаний и механика — OK/17,621 с, 1 пропуск (read-only-команда отдельно в TransactionTestCase). 3 конкурентных PostgreSQL-сценария — OK/2,261 с: одно изменение ДДК, один доступ, одно предупреждение при двух обработчиках.
- Полный Chromium-сценарий: мастер меняет шлифовку на П1 и прикладывает файл; руководитель выдаёт доступ; арендодатель смотрит только свой табель без денег, скачивает Excel, отправляет разногласие; руководитель рассматривает его. Ширины 320/390/1440 без распирания страницы — OK. Первоначально тест использовал раскрывающийся элемент старой формы, затем в нём исправлены выбор поля и ожидания завершения навигации; текущая форма и права не ослаблялись ради теста.
- Заключительные 18 PostgreSQL/Chromium-сценариев — OK/23,697 с, включая прежнюю загрузку фото, полный внешний процесс и конкуренцию. Тест обратного/прямого перехода maxbot.0005→0006 сохраняет digest/version прежнего наблюдателя и ставит только format_version=1 — OK/0,445 с.
- 4 PostgreSQL TransactionTestCase с read-only диагностикой — OK/2,941 с; 95 заключительных тестов SQLite обычного Excel, новых числовых колонок, ПТО и уведомлений — OK/15,889 с; 23 теста ролей/отзыва — OK/1,869 с; отдельные 9 сценариев доступа, включая закрытие для неактивного владельца — OK/0,907 с.
- Проверки Django, отсутствие незаписанных миграций, синтаксис JS и diff — успешны. Тестовые данные синтетические, снимки/проверочные документы вне Git. Настоящие MAX API/VPS/рабочая база не вызывались.

Предыдущая ведомость ПТО установлена по выводу владельца (Healthy всех трёх служб, check OK); это не прямой просмотр сервера разработчиком. Новый пакет после установки требует создать конкретную учётку арендодателя и явно предоставить аренду. Установщик этого автоматически не делает.

Контейнерный профиль выполнен под штатным непривилегированным пользователем с отключённой сетью, read-only root и /tmp tmpfs: 45 тестов — OK/7,033 с. Использован прежний образ с теми же закреплёнными зависимостями и подключённое проверенное дерево server; все его файлы сверяются с исходниками комплекта. Новый производственный образ соберёт установщик на VPS. Первая попытка bind-mount исходного каталога не запустила Python из-за прав host-файлов; для проверки создана отдельная копия публичных исходников с нормальными правами чтения, без изменения рабочего дерева/секретов. Новых зависимостей нет.
