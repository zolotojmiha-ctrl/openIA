## Подпись и распространение

Ключ подписи владельца — `armada-release-signing.key.pem`, отпечаток SHA-256 DER SPKI `e2f6b26419ccb10faa61baf1cfb5a0ea53f499da8803f23f0dd0df3f420aa3e4`. Это не SSH-ключ и не ключ восстановления. Закрытый ключ остаётся на Mac; помощник сам проверяет прежнее подписанное подтверждение восстановления 6.33.1 из публичной основы release_6332_baseline, не меняя дату и не запуская восстановление снова.

Публичный ответ `armada-6.33.3-public-signatures.zip` уже получен и проверен; следующие инструкции абзаца описывают выполненную публикацию. Скачать его через механизм вложений, проверить состав и воспроизводимость `tools/assemble_signed_6333.py`, сверить доверенный отпечаток и источник, затем публиковать подписанный внешний `armada-6.33.3.zip` обычным GitHub-путём. GitHub Environments/Secrets не нужны. Временные тестовые ключи и подписанные ими копии из облачного стенда не являются выпуском владельца и не публикуются.

Подготовку и тесты выполнять в облаке. Mac используется только для подписи. Команды SSH и команды root на VPS выдавать отдельно и ясно подписывать место выполнения. Адрес/действующий SSH-ключ брать из контекста владельца, не угадывать. Корень приложения /opt/armada, штатный env — deploy/beget/.env. Стандартный установщик перед боевым переходом делает свежую зашифрованную копию нынешнего наполнения и сохраняет состояние MAX-worker. Не требовать скачивания старого реального backup для повторения уже подтверждённого восстановления без изменения формата/диагнозa.
