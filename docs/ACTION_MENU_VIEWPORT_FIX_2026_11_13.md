# Меню действий на узком экране

Владелец показал обрезанное слева меню «⋯» на странице работ участка на iPhone. Причина воспроизведена на реально отрендеренной странице с синтетическими данными: общий CSS привязывает правый край панели к правому краю кнопки; при левой кнопке панель шириной 220 px начинается на x=-154 px.

Общая логика `accounts/interface.js` ограничивает панели `.action-menu` и `.inline-menu` видимой областью с полями по 12 px. Ширина ограничена видимой областью и прежними 290 px; пересчёт выполняется при открытии, изменении размеров окна/VisualViewport и прокрутке. Положение кнопок и расположение пунктов не меняются. CSS ограничивает текст коробкой панели. Версии URL обоих ресурсов в базовом шаблоне изменены, чтобы браузер после перезагрузки получил новые ресурсы.

Проверка Chromium на трёх отрендеренных страницах (работы участка, карточка объекта, общий реестр) и ширинах 320/390/430/768/1440: 15 открытий меню, все границы внутри экрана, без обрезанного текста/горизонтального выхода страницы. При открытом меню проверено изменение ширины 390→844→320, Escape и нажатие снаружи. Исходный дефект подтверждён старой версией ресурсов; сделаны снимки до/после, исправленный снимок просмотрен. Ошибок JavaScript нет; `node --check` проходит. Физический iPhone/Safari разработчиком не проверялся. Код приложения/БД/права и содержимое меню не менялись, миграций нет. Для этой визуальной правки новые прикладные тесты в репозиторий не добавлялись.

Отдельный подписанный пакет содержит только два статических ресурса и базовый шаблон; установщик проверяет исходные файлы, сохраняет данные/исходники и собирает образ, затем запускает web/mailworker и ранее работавший MAX. Требуется предыдущее исправление обзорного доступа; его миграция/права сохраняются. После установки обновить страницу в браузере.

Владелец ранее подтвердил установку accounts.0029 и Healthy трёх служб. Фактическая выдача обзорного разрешения и недостающего объекта сотруднику пока не подтверждена; эта визуальная правка её не выполняет.
