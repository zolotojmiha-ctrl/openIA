# АРМАДА 6.16.1 — действия с контрактами, участками и дефектами

Пакет поверх 6.16.0. Сохраняет имеющиеся учётные записи, пароли, документы, почту и историю работ.

- Контракты заказчиков и договоры контрагентов получили действие «Удалить» с отдельным подтверждением и проверкой версии. Файлы сохраняются в документах; участки сохраняются отдельно. Работы, финансовые записи и другая связанная история блокируют удаление с перечнем зависимостей: автоматического каскадного удаления нет. Архивирование остаётся отдельным действием.
- На каждой карточке участка внутри контракта есть меню «⋯»: редактирование и удаление. После редактирования из контракта возврат ведёт в тот же контракт. Существующая защита удаления участков со связанными записями сохранена.
- РНУ хранится в отдельном необязательном поле контракта. При добавлении дефекта контракт и участок берутся из текущей страницы, РНУ подставляется автоматически. Для старых данных используется единственное однозначное РНУ из ведомостей; если его нет, можно один раз указать его в контракте или при первом дефекте. Свободный текст номера контракта не разбирается догадками. Единственный уже заданный нефтепровод участка также подставляется автоматически.
- Руководитель видит всех активных пользователей с ролью «Мастер / прораб», включая мастеров без доступа к выбранному участку. При отсутствии доступа форма объясняет причину и требует явного флажка открытия доступа. При сохранении создаются доступ к участку и минимальная карточка контракта (номер и предмет). Финансовые сведения и индивидуальные разрешения на чужие файлы не выдаются. У делегированных сотрудников прежние границы полномочий сохранены. Отзыв доступа по-прежнему закрывает просмотр и отправку результатов.
- Внутри участка и в общем списке используется одна таблица дефектов с одинаковыми действиями, фильтрами и пагинацией. Кнопка, открывавшая альтернативную ведомость того же участка, убрана. Вместо «Изменить данные» — «Редактировать дефект: данные и координаты». В меню отдельно есть «Открыть карточку», внесение результата и удаление дефекта.
- Возврат из карточки сохраняет исходную страницу, контракт, участок, фильтры и страницу списка. Положение прокрутки хранится в текущей вкладке браузера. Контекст проходит через формы результата и переназначения; внешние адреса возврата отклоняются.
- Исправлен контраст кнопки «Добавить участок работ»; CSS обновляется с версией, чтобы старый кэш не скрывал текст.

## Установка Beget

На сервере из `/opt/armada/openIA-feature-accounts-foundation` сначала выполнить `bash deploy/beget/backup.sh`. Распаковать архив поверх существующего дерева. Файл `deploy/beget/.env` в архив не входит и сохраняется. Затем:

```sh
docker compose -f deploy/beget/compose.yml build web
docker compose -f deploy/beget/compose.yml up -d
docker compose -f deploy/beget/compose.yml ps
```

Инициализатор применяет новую миграцию `projects.0016_contract_rnu`. Том базы, документов и ключей остаётся прежним. Повторно создавать руководителей или удалять тома не требуется. После установки обновить страницу с очисткой кэша: ⌘+Shift+R.
