# Проверки 6.13

Выполнено 26 октября 2026 на отдельной установке разработки. Настоящие NAS, VPS, DNS и почтовые ящики заказчика не использовались.

- **498 серверных тестов на PostgreSQL 17 — успешно**, включая параллельную отправку одной очереди, конкурирующие исправления и проверку работ, предыдущие права/профиль/пароли, ведомости, бригады, технику, склад, субподряд, закрытие, документы, финансы и ремонт.
- **16 браузерных сценариев — успешно**: прежние рабочие разделы и новый сценарий «почта + ежедневные работы». Для последнего проверены ширины 320, 390, 768 и 1440 пикселей, ответ на письмо, очередь, возврат отчёта, исправление ширины 300 → 200 и подтверждение с сохранением истории.
- **43 дополнительные проверки — успешно**: почта, ежедневные работы, новый браузерный сценарий и ограничения локального режима. Это повторные/дополнительные проверки, а не ещё 43 уникальные функции.
- В почтовые проверки входят **два настоящих локальных TLS-сеанса IMAP/SMTP** с тестовым сертификатом и синтетическими письмами. Проверка сертификатов и имени сервера включена. Внешним адресатам письма не отправлялись.
- Production Compose: отдельные временные тома/сеть, DEBUG выключен, защищённые cookies, вход через HTTPS-признак доверенного прокси, изначально пустая база, запуск фонового обработчика.
- Выполнен настоящий `backup.sh` и восстановление дампа PostgreSQL в новую тестовую базу. Проверены пароль пользователя, расшифровка реквизитов ящика прежним ключом, приватный документ и контрольные суммы. Синтетический ящик оставался заявкой: фоновой связи с Beget не было.
- Caddy: конфигурация прошла `caddy validate`. Настоящие DNS и сертификаты домена этим тестом не проверялись.
- Django check, отсутствие пропущенных миграций, `git diff --check`, shell-синтаксис backup.sh — успешно.

Основные тесты: `server/postoffice/tests.py`, `test_transport.py`, `test_concurrency.py`, `test_browser.py`; `server/projects/test_daily.py`, `test_daily_concurrency.py`; `tests/mail-daily-browser.cjs`; `tests/beget-smoke.py`.

Проверка production/копии запускается на машине разработки с собранными образами `armada-web:6.13.0` и `armada-db:17`:

```sh
python tests/beget-smoke.py
```

Она создаёт только случайный тестовый проект `armada-verify-*`, затем удаляет его собственные тестовые тома. Публичный прокси и реальные почтовые соединения не запускаются. Не заменяйте случайное имя на имя рабочего проекта.

## Что ещё нужно проверить на настоящей установке

Перенос данных NAS, вход существующих сотрудников на VPS, сертификаты после смены DNS, реальные IMAP/SMTP-реквизиты и тариф Beget, получение/отправка контрольного письма, доступ двух руководителей и внешняя копия резервного архива. Автоматическое создание ящиков через API провайдера, полный offline-режим и включение представителей субподрядчика в новый ежедневный журнал не реализованы; это явно отражено в RELEASE_6_13.md.
