# Армада Управление 6.31.0 — надёжное обновление и резервирование

Накопительный выпуск поверх 6.30.0 с MAX, подготовка согласована владельцем 10 ноября 2026. Прикладной формат данных/миграции не меняются. MAX остаётся выключенным по умолчанию; раньше активный worker возобновляется только после успешной проверки.

- Запись непрерывно остановлена от начала резервной копии до завершения миграций/проверки. Установщик использует новую реализацию backup.sh даже на старой установке; один backup.lock удерживается на всём интервале. Самостоятельная копия возобновляет прежние службы, в том числе после ошибки.
- До первой попытки миграций возможен автоматический возврат старого дерева/точных image ID; после неё — остановка писателей и закрытый checkpoint с RECOVERY.md и точным архивом. При недоступном Docker остановка не считается подтверждённой. Откат схемы автоматически не выполняется.
- Код заменяется целиком, удалённые файлы не остаются в активном дереве. .env/.env.*, владельцы/права существующих файлов и inode блокировки сохраняются. Имя Compose/томов прежнее, действующая БД и init автоматически не пересоздаются.
- Локальное шифрование на открытый ключ опционально; закрытый ключ вне VPS. Политика 7 копий/30 дней дополнительно сохраняет последнюю действительно восстановленную копию и все более новые. Без подтверждения удаления нет. Отдельный доверенный стенд может периодически восстанавливать копию в PostgreSQL без сети, сверять строки и файлы; приватный ключ остаётся там. Яндекс Диск использует существующее подключение, реальный API не проверялся и автоматически не включался.
- Подпись SHA256SUMS проверяется независимым публичным ключом. Установщик отказывается работать без подписи/ключа/OpenSSL, при подмене архива, своего файла, метаданных либо неподтверждённом статусе выпуска. Закрытая часть ключа подписи не входит в Git/ZIP; это отдельный ключ, не ключ восстановления и не пароль пользователя.
- Служебные корневые документы/старые черновики/тестовые средства исключены из установочного ZIP. Исторические пути deploy/synology сохранены совместимыми. Домены параметризованы; PostgreSQL/Python base закреплены digest. У веба cap_drop=ALL и pids_limit=128; tar получает необходимый DAC_OVERRIDE только для закрытого резервирования. Добавлена ограниченная CSP objects/base/framing, прежние заголовки и индивидуальные политики файлов сохранены. Строгая nonce/script-src CSP в этот выпуск не входит.

Архив из неизменяемого коммита, образ из этого ZIP, полный PostgreSQL 17/Chromium-прогон конечного кода и испытания обновления/ошибок/восстановления должны завершиться до допуска к установке. Исторические 6.29.0/6.30.0 не переписываются. Рабочий VPS/Figma, настоящие MAX/SMTP/Яндекс, публичный HTTPS и клиентские данные не используются. Итоговые значения и фактические ограничения — во внешнем VALIDATION.md рядом с пакетом.
