# Четвёртый этап — склады, 6.4.0-stock

Рабочая серверная реализация поверх 6.3. NAS не обновлялся.

## Порядок работы

1. Руководитель создаёт склад с названием и местом хранения. При необходимости указывает объект. Для материалов у бригады создаётся отдельное место хранения с её датированным назначением из этапа 6.2. Один такой склад относится к одному назначению.
2. Для кладовщика, снабженца, техника или другого сотрудника выдаётся отдельное право «Вести склады, остатки и движение материалов» (`stock.manage`). Должность сама по себе не даёт полномочий. Другому сотруднику можно отдельно открыть только просмотр выбранного склада. Эти действия не выдают доступ к объектам, контрактам или документам.
3. В «Материалы и муфты» создаётся номенклатура: код, название, единица, вид; для муфт — метод П1–П5У, длина, целая толщина стенки, при необходимости диаметр. Можно вести типовые изделия количеством либо связать позицию с одной конкретной муфтой из реестра ремонтов.
4. Начальные остатки вносятся операцией «Поступление». Наличие старого текстового места хранения у муфты не создаёт складского остатка. Уже установленные и исторические изделия в новый остаток не переносятся автоматически.
5. «Перемещение» — между обычными складами. «Выдача бригаде» — с обычного склада на место хранения, связанное с назначением бригады. «Возврат» — обратно на обычный склад. Проверяются период назначения и доступ уполномоченного сотрудника.
6. Материалы и типовые муфты списываются на выбранную работу отдельной операцией «Списание на работу». Для недостачи или иного списания есть самостоятельная операция с обязательным основанием. Количества измеряются до трёх знаков; штучные изделия — целым количеством.

## Конкретные муфты и простой интерфейс мастера

Связь позиции с конкретной муфтой — явный выбор при создании номенклатуры. Одно изделие нельзя принять дважды или одновременно держать в двух местах. При выдаче на склад объекта / бригаде привязка ещё не установленной муфты к объекту обновляется явно, с проверкой доступа и уникальности заводского номера.

Если при выдаче конкретной муфты бригаде выбрана определённая работа, её объект, мастер и метод должны совпадать с выдачей. В простой форме мастера «Устранён» показывается подготовленный перечень изделий. Повторно вводить номера не требуется: результат установки и списание сохраняются вместе. Изменившаяся выдача требует перепроверки формы. Выдача без выбранной работы сама по себе не означает установку на произвольный дефект.

В подробном результате можно явно выбрать конкретные изделия. Если они связаны со складским учётом, проверяется остаток и доступное место хранения. Списание появляется автоматически при сохранении результата, до проверки руководителем: это факт установки по сведениям мастера. Само подтверждение не списывает повторно. Возврат результата на доработку не возвращает физически установленную муфту на склад.

При исправлении состава установленных муфт создаются обратные складские записи и новые списания. Прежние результаты, авторы, фотографии и операции сохраняются. Исправление ремонта и изменения остатков выполняются в одной транзакции; ошибка отменяет всю операцию. Старые муфты без явной связи с номенклатурой продолжают работать по прежнему сценарию, без выдуманного остатка или автоматического списания.

## Контроль остатков и отмена

Отрицательный остаток запрещён. Проверка, проводки и остатки сохраняются вместе. Изменения сериализованы по компании; это предотвращает двойной расход при параллельной работе пользователей. При повторной отправке одного запроса операция не дублируется.

Операция не редактируется задним числом. «Отменить с пояснением» создаёт обратную запись, если остатка хватает. Автоматическое списание конкретной муфты исправляется через результат ремонта. Перемещение конкретного изделия возвращается отдельным обратным перемещением, чтобы сохранить привязку к объекту. Архив склада и позиции разрешён только при нулевом остатке. Размеры и единицы номенклатуры с историей не переписываются: создаётся другая позиция.

Система показывает текущие количественные остатки. Фактическая дата хранится у операции; отдельный расчёт исторических остатков на произвольную дату и стоимостной складской учёт этим этапом не заявляются.

## Интерфейс и доступ

В боковом меню и на главной есть «Склады». В карточке объекта — вкладка складов этого объекта с учётом прав. Реестр показывает остатки и историю; на телефоне строки складываются без горизонтального смахивания таблицы.

Просмотр склада выдаётся отдельно. Операции между складами не раскрывают закрытую вторую сторону сотруднику без права её просмотра. Права на файлы, финансовые данные, объекты и контракты сохраняются. Складские проводки не создают финансовые расходы автоматически. Изменения справочников, выдача доступа и операции записываются в аудит.

## Excel

Есть XLSX-шаблоны, экспорт и импорт складов, номенклатуры и операций, а также отдельный экспорт текущих остатков. Сначала создаются склады и номенклатура, затем движения. До 500 строк за перенос, даты — ГГГГ-ММ-ДД. Формулы не исполняются.

Перед переносом проверяется весь файл без сохранения. При подтверждении права, версии и остатки проверяются повторно. Ошибка одной строки отменяет весь перенос. Повторное подтверждение одного просмотра безопасно. Новая строка без ID при новом импорте — новая операция; повторная загрузка другого файла с такими строками не является автоматической сверкой накладных.

Для изменения карточки сохраняются ID и версия. Проведённая операция с ID не переписывается. Пропуск строки не удаляет запись. Остатки не заменяются числом из Excel: для начального остатка — поступление, для исправления — явные операции с основанием. Это сохраняет проверяемую историю количества.

## Остальные этапы

Согласованные функции не отменены. Полноценные компании-субподрядчики, их договоры, документы и ограниченный доступ, производственный учёт иных видов работ, закрытие контрактов, многостраничные документы и расширенный автономный режим остаются следующими этапами. Текущий этап не выдаёт количественные складские операции за бухгалтерский / стоимостной учёт.
