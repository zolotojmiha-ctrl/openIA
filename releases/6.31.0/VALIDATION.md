## Границы инфраструктурного испытания

Приложение — настоящий образ из ZIP, read-only/UID10001/cap_drop ALL/pids_limit128. Из-за VFS тестовый PostgreSQL-контейнер использовал тот же бинарный PG17.11, штатный entrypoint и неизменённый 10-create-app.sh, подключённые read-only; системные библиотеки/локаль/zoneinfo предоставлялись хостом. Это не проверка точного полного rootfs образа провайдера. DB имел реальную парольную аутентификацию/роли, отдельную internal-сеть и tmpfs, без публичных портов/рабочих томов. ID DB проверен неизменным после обновления. Proxy и mailworker заменены sleep-процессами; настоящий MAX работал без --deliver. Docker socket был только во временном root-runner. ZipFile shim воспроизводил структуру/Unix-права/время ZIP, контрольные суммы/подпись/логика установщика выполнялись штатно. Привилегии DAC_OVERRIDE/CHOWN добавлялись только синтетическим подготовительным ORM-процессам; runtime web оставался без capabilities. Закрытое tar-резервирование получает только DAC_OVERRIDE.

Ранние ограничения стенда/попытки отделены: необходимость сохранить завершённый init, экспорт кода от UID приложения, подстановка публичных библиотек и прав в минимальном тестовом PG. Обнаруженная реальная несовместимость запроса maxworker на старом Compose исправлена до конечного коммита и полного прогона. Старый тестовый комплект остановлен намеренно до изменений. Для места удалены только собственные доказанно неиспользуемые промежуточные 6.31-образы/точный кэш и повторные проверочные ZIP с сохранённой идентичной канонической копией и хэшами; старые image ID 6.29/6.30 и их архивы не изменялись. Настройки managed-среды не сохранялись/не публиковались.

## Перед настоящей установкой

- Проверить восстановленный VPS, фактическую версию, данные и место; установщик для существующего штатного приложения, не пустого VPS. Для нового сервера сначала отдельное развёртывание и восстановление. Особые локальные изменения Compose/томов требуют сверки.
- Независимо получить публичный ключ подписи, сверить его fingerprint и проверить подписанный манифест до запуска. Установить публичную часть root-owned; закрытую часть подписи хранить отдельно на Mac, не на VPS и не в Git/ZIP. В тестах был другой временный ключ, окончательный комплект подписывается ключом владельца после этого протокола.
- При первой попытке миграций барьер считается пересечённым даже при неоднозначном сбое Docker. После этого восстановление ручное по RECOVERY.md: остановить стандартные и посторонние писатели, восстановить БД/файлы/config вместе. При недоступном Docker команда остановки не считается подтверждением фактической остановки.
- MAX/Webhook/CDN/реальные отправки и Яндекс Диск требуют подключения/пилота; OAuth/recovery-ключ не получены. Автоматическая проверка должна работать на доверенном хосте с отдельным recovery-ключом, а не на VPS. Retention без receipt сохраняет всё, поэтому нужен контроль места. Яндекс Диск не является immutable-хранилищем.
- CSP ограниченная: objects/base/framing, не строгая nonce/script-src политика. У локально собранного armada-db:17 нет registry digest; можно закрепить точный ID/registry digest параметром ARMADA_DATABASE_IMAGE. Существующая БД автоматически не пересобиралась.
