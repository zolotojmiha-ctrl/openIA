# Армада Управление 6.31.0

Проверенный локальный накопительный выпуск с MAX и защитой обновления/резервирования. Производственный сервер не обновлён. MAX сам не включается.

Состав: ZIP, установщик, подписанный манифест/JSON, окончательный VALIDATION.md, Git-bundle и код синтетических проверок. Закрытых ключей, конфигураций, дампов и производственных данных нет. Закрытый ключ подписи хранится отдельно у владельца; публичный получить независимым доверенным способом, а не из этого архива.

До запуска установщика проверьте подпись и хэши (Mac):

```bash
openssl dgst -sha256 -verify /private/armada-release-signing.public.pem -signature SHA256SUMS-6.31.0.sig SHA256SUMS-6.31.0
shasum -a 256 -c SHA256SUMS-6.31.0
```

После восстановления Beget сначала проверить данные/версию. Установщик предназначен для существующей штатной установки, требует root, Python3.9+, OpenSSL и BuildKit; на пустом VPS сначала развёртывание/восстановление. Соседние ZIP/подписанный манифест/JSON используются локально; скачивание из GitHub возможно только после отдельной публикации. Публичную часть установить root-owned в /etc/armada/release-signing-public.pem. Закрытую часть на сервер не переносить.

Протокол и дополнительные файлы связаны хэшами в подписанном JSON. README внутри ZIP относится к полным исходникам Git; актуальный протокол — внешний VALIDATION.md. VALIDATION_TOOLS.zip — код для отдельного Linux/Docker-стенда, не запускать на рабочем VPS.

Ключ подписи и ключ расшифровки резервных копий — разные ключи. Для локального шифрования можно на доверенном компьютере получить recovery-public.pem из сохранённого recovery-private.pem командой openssl pkey -in recovery-private.pem -pubout -out recovery-public.pem, затем на VPS передавать только recovery-public.pem. Само расписание/настройки внешнего хранилища не включены. Параметры KEEP/DAYS/PUBLIC_KEY для systemd задаются администратором в drop-in службы, не через публикацию секретов. Перед очисткой старых копий необходимо подтверждение настоящего восстановления.
