# Проверки 6.14

Выполнены на отдельной установке разработки. Настоящие данные и сервер заказчика не изменялись.

- **508 серверных тестов PostgreSQL 17 прошли**: новый реестр договоров, права, проверка связанного объекта и дат/сумм, устаревшие формы, архив/восстановление, Excel с предварительным просмотром и защитой от повторного применения, фильтрация почтовых уведомлений, счётчики, статус чтения, карточка работника без аккаунта и статусы документов техники. Включена регрессия прежних контрактов, пользователей/паролей, документов, ремонтов, бригад, техники, склада, субподряда и финансов.
- Браузерные сценарии прежних разделов проверены; один старый сценарий требовал обновить селектор переименованного пункта меню «Выполнение работ», затем прошёл повторную проверку. Новый сценарий создаёт договор аренды жилья, выбирает существующие контракт заказчика и объект, проверяет сохранение и отсутствие дублирования контракта. Проверены ширины 320/390/768/1440, загрузка Apple touch icon и отсутствие ошибок JavaScript. Всего проверены 16 браузерных сценариев.
- **Переход 6.13 → 6.14 проверен на настоящем Docker/PostgreSQL**: создана предыдущая установка с синтетическим пользователем, паролем, контрактом, работником без аккаунта, техникой, документом и зашифрованными реквизитами ящика. После смены образа и миграций все эти данные и возможность расшифровки сохранены, новый реестр изначально пуст.
- Выполнено резервное копирование обновлённой установки и восстановление дампа в новую тестовую базу. Проверены прежний пароль, контракт, работник, техника, ключ и документ, контрольные суммы архива.
- Django check, отсутствие пропущенных миграций и git diff --check прошли.

Код новых проверок: `server/projects/test_update614.py`, `test_update614_browser.py`, `tests/update614-browser.cjs`, `tests/beget-smoke.py`.

Для воспроизведения проверки перехода нужны собранные образы обеих версий и PostgreSQL:

```sh
python tests/beget-smoke.py --upgrade-from=armada-web:6.13.0
```

Она работает только в случайном отдельном проекте `armada-verify-*` и удаляет только его тестовые тома. Не заменяйте имя на имя рабочего проекта. Почтовый ящик в тесте остаётся заявкой: внешние письма не отправляются, публичные сертификаты не запрашиваются.

На рабочем Beget после установки ещё нужно проверить вход, прежние карточки и файлы, отправку почты и отображение нового реестра. Реальное обновление выполняется пользователем по UPDATE_BEGET_6_14.md; исходники и архив сами по себе сервер не обновляют.
