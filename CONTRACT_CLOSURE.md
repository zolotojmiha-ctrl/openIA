# Закрытие и восстановление контрактов

Первый рабочий этап процедуры закрытия, поверх 6.5.0-subcontracts.

В карточке контракта сотрудник с явно выданным projects.manage подаёт заявку с пояснением. Должность техника сама по себе полномочий не выдаёт. Руководитель видит очередь в разделе «Договоры», подтверждает архивирование либо возвращает заявку с объяснением. Восстановление выполняет руководитель с обязательной причиной; возвращается состояние до архивирования. Старые архивные контракты без событий восстанавливаются в состояние «В работе».

Каждое решение сохраняется отдельной записью: автор, время, действие, причина, прежнее состояние. Версия контракта предотвращает повторные и устаревшие решения. Доступ проверяется повторно внутри транзакции; права на документы и объекты не расширяются. Архивирование убрано из обычной формы состояния.

Границы этапа: архивирование меняет состояние контракта, но пока не является общей блокировкой всех операций по нему. Перед подтверждением руководитель проверяет работы, документы, расчёты и назначения. Автоматические проверки полноты закрытия, общий режим чтения архива и уведомление на главной ещё требуют отдельной реализации. Заявки доступны в «Договорах»; это не заявление о готовности полного регламента закрытия. Связанные назначения, остатки и субподряды не закрываются автоматически.

NAS не изменялся. Обновление для установки пока не выпускалось.

Проверено: 337 функциональных тестов SQLite прошли (включая 6 новых сценариев закрытия), Django check, проверка отсутствия незаписанных миграций, git diff --check. Проверки PostgreSQL и браузерные сценарии для этого этапа пока не запускались.
