# Проверки кандидата 6.33.1

Исторический отчёт разработчика: RELEASE_6_33_1_VALIDATION.md. Он описывает имитации, не реальные контейнеры. Независимая облачная проверка использует Linux, Python 3.12, Docker 29 и Compose 2.40, PostgreSQL 17, только синтетические данные. Точные версии, коммит, коды выхода, результаты и журналы заключительного прогона находятся в CLOUD_VALIDATION.md и evidence/ рядом с итоговым кандидатом.

## Проверено до заключительного прогона

- Реальная офлайн-установка зависимостей по хэшам и сборка приложения.
- Работа стенда 6.33.0 и HTTP 200 страницы входа, команды du и pg_database_size в реальных контейнерах.
- Обновление до 6.33.1 с тестовой подписью; MAX, который не работал прежде, не включился.
- Восстановление зашифрованной предустановочной копии в отдельном PostgreSQL 17.
- Отказ при несовпадении числа строк, без квитанции успеха.
- Воспроизведение и исправление перезаписи имени контейнера вложенным именем файла, остатков открытого архива после ошибок/TERM, фиксированного имени в Mac-квитанции.

## Не проверено и ограничения

- Реальная копия владельца, Mac/Apple Silicon, причина прежнего отказа. Проверяет владелец на доверенном хосте; разработчику только обезличенная диагностика.
- Production VPS, внешние MAX/webhook/почта/HTTPS/Яндекс Диск, производственная подпись и публикация.
- Физическое исчерпание отдельных томов, btrfs/zfs, rootful Docker VPS. Отказы по месту проверяются в изолированных сценариях с подменённым df; bind-mount точки одного источника суммируются; одинаковые общие имена источников могут дать избыточную оценку. Формула остаётся оценкой, а не гарантией пикового расхода Docker build.
- Docker облака rootless без поддержки cgroups: успех восстановления не доказывает достаточность лимитов памяти Mac. Порог размера сжатого архива не ограничивает распакованный размер; лимиты Mac — ограниченный профиль, не доказательство причины отказа.
- SIGKILL/потеря питания не запускают shell cleanup; после них возможны закрытые правами 0600 незавершённые файлы. Не загружать их во внешнее хранилище.
- SQLite-тесты приложения не проверяют PostgreSQL-конкуренцию; отдельные реальные испытания восстановления не заменяют полный прикладной набор.

Кандидат сохраняет ready_for_install=false. Даже успешные синтетические испытания не снимают условие подтверждённого восстановления реальной копии.
