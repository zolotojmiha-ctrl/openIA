# Обновление установленного Beget до 6.14

Рабочая папка: `/opt/armada/openIA-feature-accounts-foundation`. Архив распаковывается в `/opt/armada`, сохраняя это имя. Выполнять после проверки контрольной суммы архива; ожидаемая сумма опубликована рядом с архивом в downloads/nas-updates.

1. На время обновления завершите ввод в ЛК.
2. В терминале сервера из существующей папки проекта выполните `bash deploy/beget/backup.sh`. Дождитесь `Backup saved:`. Если копия не создана — остановитесь до устранения ошибки. Архив приватный: содержит базу, файлы и ключи. Не отправляйте его в чат.
3. Скачайте `openIA-6.14.0-update.zip`, проверьте SHA256, распакуйте через `unzip -oq` в `/opt/armada`. Архив не содержит `.env`, баз и томов. Сохранённая настройка TLS_EMAIL останется на месте.
4. Из папки проекта выполните:

```sh
docker compose -f deploy/beget/compose.yml build
docker compose -f deploy/beget/compose.yml up -d
docker compose -f deploy/beget/compose.yml ps
```

Миграции выполняются при старте web. Дождитесь healthy у db и web, состояния Up у mailworker и proxy. При ошибке смотрите `docker compose -f deploy/beget/compose.yml logs --tail=80 web`.

**Не выполнять:** bootstrap_leaders, очистку базы, `down -v`, удаление томов. Исходные файлы обновляются, а данные остаются в существующих томах. Не переносите сюда тестовые данные разработки.

Проверьте вход прежним паролем, карточки работников/техники и прежние документы, почту, новые названия разделов. Договоры с контрагентами доступны руководителям; при открытии нового раздела прежние контракты не должны исчезнуть — они остаются в «Контракты с заказчиками».

Откат требует согласованных старой версии приложения и копии. Не восстанавливайте старую базу поверх новых данных без отдельной проверки: изменения после копии будут утрачены. Копию стоит дополнительно сохранить вне VPS; расписание внешних копий этим обновлением не включается.
