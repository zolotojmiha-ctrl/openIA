# 6.14.1 — сначала контракт, затем объекты

Исправлено обязательное поле объектов при создании контракта. Теперь можно:

1. Сохранить контракт заказчика без объектов.
2. В карточке выбрать «Добавить объект в контракт» и создать объект с уже выбранным контрактом.
3. Либо выбрать ранее созданные объекты через «Выбрать существующие объекты».

При создании объекта из контракта связь добавляется автоматически; существующие объекты и контракты не дублируются. Можно добавить несколько объектов по очереди. Поле контракта есть и в обычном создании объекта; оно необязательно.

В Excel контракт также может добавляться без списка ID объектов. Для уполномоченного редактора контракт без объектов остаётся доступен только при наличии явного доступа к этому контракту; права на другие записи не расширяются. Для привязки работ, бригад и техники по-прежнему нужен подходящий объект.

С формы убрана оставшаяся учебная надпись об использовании вымышленных данных. Контракт, заказчик, даты, сумма и остальные поля сохраняются обычным способом.

Изменения схемы базы не требуются. Перед обновлением запустите существующий `deploy/beget/backup.sh`, затем проверьте архив, распакуйте его в `/opt/armada`, выполните `docker compose -f deploy/beget/compose.yml build` и `up -d`. Базу и тома не очищать, руководителей повторно не создавать. Все функции 6.14 и исправление общего почтового ящика включены.

Проверки: создание контракта при полном отсутствии объектов, добавление нового объекта из карточки, сохранение доступа редактора к своему контракту без объектов, отказ в доступе к чужому/архивному контракту, Excel без объектов; браузерный путь с пустой установки и прежний сценарий техника; 512 проверок на PostgreSQL прошли. Сохранность данных при переходе с 6.14.0 и восстановление копии проверены отдельным Docker-тестом.
