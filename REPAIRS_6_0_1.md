# 6.0.1-repairs — кабинет мастера

Последующие уточнения координат, групп и Excel описаны в [REPAIRS_6_0_2.md](REPAIRS_6_0_2.md).

База: версия 6.0.0-repairs, коммит `913cf53324a89a5f5522f5131df9ef6aa789f4c2`
из ветки `feature/accounts-foundation`. Ветка `main` содержит только первоначальный README.
Изменения подготовлены в `repair-wizard-simplify`.

Мастер видит готовые назначенные работы с отдельными строками дефектов:
километр, номер секции, номер дефекта, тип конструкции, длина (м), толщина стенки (мм).
Для конструкции, закрывающей несколько дефектов, отправляется один общий результат,
как и в версии 6.0.0. Показания отсутствующих полей не выдумываются.

Доступны два основных действия:

- **Устранён**: дата, координаты (обязательны, вручную или через геолокацию),
  фото и пояснение по желанию. Тип, длина и состав берутся из задания на сервере;
  прежние привязки установленных муфт сохраняются. Складские изделия автоматически
  не подбираются и не списываются. При неверном задании руководитель должен уточнить его.
- **Не устранён**: болото, нет муфты, нет другого материала или другая причина.
  Последние две причины требуют пояснения. Запись переводит неподтверждённую работу в «В работе», снимая её с проверки выполнения; прежние результаты остаются в истории.

История, файлы, авторство, права на объекты, назначение мастеров, проверка руководителем,
приёмка заказчиком, защита от повторной отправки и конфликта версий сохраняются.
Подтверждённый результат исправляет руководитель отдельной записью.
Прежние маршруты внесения подробных результатов сохранены для совместимости.

## Толщина стенки

Добавлено необязательное поле `Job.wall_mm`, заполняемое руководителем в задании.
В старых заданиях оно пустое: интерфейс показывает «Не указана».
Толщина складской муфты не переносится в задание без подтверждённой связи;
существующий импорт ведомости не угадывает эту связь.
Миграция `repairs.0005` добавляет поле и причины; прежние записи не удаляются.

## Проверка и запуск в облачной среде

Python 3.12; из `/workspace/openIA`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py migrate --noinput
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py collectstatic --noinput
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py check
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py test accounts projects documents finance repairs --verbosity 1
ARMADA_DEVELOPMENT=1 .venv/bin/python server/manage.py runserver 127.0.0.1:8020 --noreload
```

Функциональный тест Chromium/Playwright: `test repairs.test_browser`.
Он проверяет мобильные размеры, два новых действия, обязательное пояснение,
координаты без фото, прежнюю историю, офлайн-черновик с фото, безопасный повтор
отправки, проверку руководителем, приёмку и назначение работ.
Дополнительная проверка прежнего прототипа: `node tests/prototype.cjs` при запущенном сервере.
Браузерные зависимости предоставляет текущая облачная среда.

NAS, его данные и конфигурация не изменены. Обновление не развёртывалось.
Установка в эксплуатации и проверка на PostgreSQL — отдельный этап;
текущие проверки выполнены на локальной SQLite и вымышленных данных.
Не применять режим `ARMADA_DEVELOPMENT=1` к рабочей установке.

  установка/инициализация — успешно.

  1440, 768, 390 и 320, без ошибок JavaScript.
